# 11 · 风险与对策

> 📌 **V0 生效范围（2026-08 范围收缩）**：风险表已按 V0 重排。
> **R4（推送通道失效）、R5（语音识别不准）、R12（ASR 成本）属 V1**——V0 没有提醒与语音，这些风险不适用；
> **新增 R13（公网发布合规与备案）**，它是 V1 的第一件前置决策，**但要在 V0 期间就知道**。

>
> V0 范围见 [08-MVP范围与版本规划](./08-MVP范围与版本规划.md) §2。
> **版本号**：**V0**（=P0，当前）/ **V1**（=P1）/ **V2**（=P2）。

> PRD 里最容易被学生忽略、但创始人最该先看的一章。
> 风险管理的目标不是"消灭风险"（做不到），而是**让风险发生时你死不了**。

## 2. R1 食品安全与法律风险（最重要）

**对策**：

1. **保守原则**：推算取更短期限（04 §5.2）；婴幼儿/药品品类强制保守并加重提示；
2. **估算标签**：所有推算结果标注"估算"，详情页常驻免责文案：
   *"估算仅供参考，请以包装标注与实物状态（气味、外观）为准；变质风险由用户自行判断。"*
3. **用户教育**：首次使用时 1 屏"使用须知"（不强制，可跳过，但设置页常驻）；
4. **条款兜底**：用户协议明确产品为"提醒工具"而非"食品安全检测"；不收集、不承诺检测数据；
5. **不碰的边界**：不做"这个还能不能吃"的判定结论，只做"预计期限"的参考提示，措辞永远是建议性。

## 3. R2 习惯养不成（弃用风险）

**对策**：

- 黄金时刻设计（02 §3 场景1）：记录发生在购买瞬间；
- 新用户首记引导（06 §3.4）：30 秒内完成第一次记录；
- 空状态/无提醒时仍有"首页横幅"价值（临期汇总）保持打开理由；
- 北极星监控：若"人均周记录 < 5 条"，优先优化记录路径，停止新功能。

## 4. R3 品类覆盖不足

**对策**：

- V1 只承诺 50 类高频品，明确"未收录品类的兜底=自定义模板"（04 §6）；
- 优先级排序：乳品/生鲜/面包/蛋 > 零食 > 药品 > 化妆品 > 日化；
- 用户修正反馈沉淀为新品类素材（04 §5.3），每周人工审核入库。

## 5. R4 推送通道失效（**V1 起生效**）

> ⏸ V0 没有提醒，本节不适用。

**对策（2026-08 平台迁移后重写）**：

- **推送通道是网页端提醒的生命线**（浏览器没有可靠的本地定时通知）：V1 早期用第三方通道（Bark / ntfy / 飞书机器人）→ 稳定后切换 Web Push；
- **双轨兜底**：推送失败/未授权时，页内横幅在下次打开网页时汇总"今日临期 X 件"，不补推骚扰；
- **⚠️ 但更根本的一条：不要把推送当承诺。** 已核实两条事实——
  ① iOS 上通知权限**一旦拒绝无法程序化重新申请**；
  ② 推送订阅会**静默失效**（系统更新 / 长期未开 / 存储回收 / 清理网站数据），
  且 `pushsubscriptionchange` 在 iOS 上**不可靠**，服务端只能靠"每次打开重新 upsert + 404/410 清理"兜底。
  因此**产品对外承诺应为"打开时一定会看到"，而不是"一定准时响"**——
  页内横幅（GWT-19）从"兜底"升级为"主承诺"；
- **通道健康监控**：不能只看"服务端发送成功"（会在静默失效时给出**虚假的好数字**），
  要看"用户随后是否打开了网页"；
- 防打扰设计（05 §3）降低关闭率；监控"提醒关闭率"（>15% 即调整频率与文案）；
- 放弃小程序的原因与推送方案的完整论证见 [TechDesign 12 §3](../TechDesign/12-Web优先方案（平台迁移决策）.md)。

## 6. R5 语音识别/解析不准（**V1 起生效**）

> ⏸ V0 没有语音，本节不适用。

**对策**：

- 确认页 = 纠错安全网，解析错了用户 1 秒可改；
- V1 用规则解析（稳定可预期），不做开放大模型解析（可控性优先）；
- 收集"识别失败"样本，每周更新解析规则与同义词库（"奶""牛奶""纯牛奶"→ 鲜牛奶）；
- **云端 ASR 代理**：录音经自有服务端转发至 ASR 服务商（腾讯云/讯飞），密钥不下发客户端；
- **⚠️ 实现前必须知道**：Chrome 的 `MediaRecorder` 产出 `audio/webm;codecs=opus`，
  **讯飞（只收 pcm/wav/speex）与腾讯云（不收 WebM 容器）都不接受**；
  必须在**浏览器端 `decodeAudioData` 归一化为 16k 单声道 WAV** 后再上传。
  详见 [TechDesign 12 §6.1](../TechDesign/12-Web优先方案（平台迁移决策）.md)。
- 验收双口径：解析准确率 ≥ 80% + 确认页修改率 ≤ 30% + 最终保存成功率 ≥ 90%（03 F-01）。

## 7. R6 竞品与大厂下场

**对策**：

- 差异化护城河：① 气候感知推算（需要真实数据积累）；② 生活化品牌心智（内容资产）；
- 先发数据：知识库校准样本、用户修正数据是后来者难以快速复制的；
- 大厂做"保质期"往往只是智能冰箱/买菜 App 的附属功能，专注度不如我们——专注即壁垒。

## 8. R7 单人开发风险（生病/考试/倦怠）

**对策**：

- 一切文档化：PRD、验收标准、代码注释齐全，中断 1 个月可无缝续接；
- 一切配置化：规则/文案远程更新，核心逻辑不轻易改动；
- 节奏管理：每周只做一件事（08 §4）；状态差做低脑力活（09 §6）；
- 应急：Serverless + Git，云上无单点；若长期停滞，优先"冻结"而非"烂尾"（保留可发布状态）。

## 9. R8 隐私事故

**对策**：

- 本地优先架构（07 §1）：照片/明细默认不上云，事故面最小；
- 最小收集：埋点匿名化，不采集通讯录/位置轨迹（城市由用户自填）；
- 透明承诺：设置页明示数据去向；隐私承诺本身就是营销素材（"你的冰箱只有你知道"）。

## 10. R9 冷启动失败

**对策**：

- 先建 20 人内测群再写代码（需求验证前置）；
- 内容渠道先行（10 §2），产品未上线就有选题积累；
- 每周复盘必须有"用户原话"引用，防止自嗨。

## 11. R10 推算逻辑复杂度失控

**对策**：

- 分期交付：**V0 手动气候档**（1 个 JSON 系数表）→ **V1** 天气 API；
- 规则引擎三层解耦（04 §1），任一层可独立回退；
- 复杂度上限约定：新增规则必须能写进一行 JSON，否则重新设计。

## 12. R11 服务端持有"提醒计划"（隐私面扩大）

**对策**：

- **最小字段集**（TechDesign 12 §7）：服务端只存 itemId / 显示名 / 到期日或窗口 / 提醒策略 / 推送目标
  ——不含照片、备注与完整明细；
- **自建优先**：V0 服务端即本人所有（自己的 Cloudflare 账号或自有服务器），数据不出自己的账号；
- **一键删除**：删除物品即删除服务端提醒计划；设置页提供"清空云端提醒计划"；
- **隐私说明页如实声明**"提醒计划会上传至服务端"（07 §1.3）；
- V1 产品化时重新评估是否收紧为"端侧计算 + 最小上报"（08 §3）。

## 13. R12 云 ASR 成本失控

**对策**：

- **每日用量上限**（如 100 次/日）+ 频控（同一用户 1 分钟内 ≤ 5 次）；
- **失败重试上限**（≤ 2 次）→ 超出直接降级手动表单（原 GWT-04）；
- **录音时长上限**（如 ≤ 15 秒，超时截断）——记录一句话本来就短；
- **成本看板**：每周复盘记录 ASR 用量与费用（09 §8 复盘模板加一行）；
- 备选：V2 原生 App 后用系统级 ASR（免费），按量成本归零（TechDesign 12 §6）。

## 14. R13 公网发布合规、备案与域名可达性（**2026-08 新增**）

> 🎯 **这是 V1 的第一件前置决策**。V0 **不需要**解决它，但**必须在 V0 期间知道它的存在**——
> 因为它决定 V1 的托管选型，临时改代价很大。
>
> **背景**：全部 27 份文档此前**一次都没有提到"备案"两个字**（上一轮审查发现）。

**风险的具体形态**（技术核实后）：

| 事实 | 后果 |
| ---- | ---- |
| 面向中国大陆用户的公网站点，实践中通常需要 **ICP 备案**；备案要求**境内主体 + 境内接入服务商** | Cloudflare 不提供备案通道 |
| Cloudflare 的**自定义域名要求域名处于你自己的 Cloudflare zone**（免费/Pro 仅支持 Full setup = **必须把 NS 迁到 Cloudflare**） | **迁 NS 与备案互斥**——会丢掉境内 CDN 与备案接入资格 |
| `*.workers.dev` 虽**自带有效 HTTPS、无需域名**，但官方明确**不推荐用于生产** | 且该域名在国内**常被污染/不可直连** |
| 而 PWA 的三件事（安装到主屏、Service Worker、Web Push）**都必须走 HTTPS 且域名可达** | **正好打在产品生命线（提醒通道）上** |

**对策**：

1. **把合规与部署路径当作一个显式决策点**，在 V1 启动前完成（不是 V1 中途）；
2. 路径 A（面向境内用户）：**域名 + 境内轻量服务器 + ICP 备案**——
   成本约 `60 元/年 + 24~60 元/月`，周期约 1~3 周（备案审核）；
3. 路径 B（境外访问为主 / 自用为主）：留在 Cloudflare，接受可达性风险，**但不要假设境内用户能稳定访问**；
4. **架构上已为此做好准备** ✓：`packages/core` 是纯 TS、配置是 JSON、API 是标准 REST——
   **从本地 Node 迁到云端的成本是可控的**，这正是 V0 坚持"逻辑与平台解耦"的回报；
5. 顺带在成本表里补上此前漏掉的项（[09 §5](./09-一人公司工作流.md)）：域名、备案时间成本、境内服务器、短信/邮件（若账号体系升级）。

> ⚠️ **本节不是技术判断，是合规判断**。具体是否需要备案、走什么路径，
> 请以主管部门与接入服务商的最新要求为准。

## 15. R14 越权访问（**V0 的头号安全风险**）

> 原文档最担心的隐私风险是"云端泄露"。V0 有真实账户之后，**实际最高频的严重 bug 是越权**。

**风险形态**：A 的 token 能读到 / 改到 / 删掉 B 的物资。这类 bug 一旦发生，是**数据完整性问题**，
比"泄露"更直接地毁掉信任。

**对策（必须逐条落实）**：

- **归属校验铁律**：所有物资读写必须 `WHERE id = ? AND user_id = ?`；**禁止只按 id 查**；
- `user_id` **只允许来自会话**，绝不接受客户端传入；
- 物资查询只走 `apps/server/src/services/`，且**函数签名第一个参数恒为 `userId`**；
- **必须有自动化测试**：用 A 的 token 对 B 的物资执行**列表/详情/修改/删除**四个动作，全部返回 **403/404**；
- 配套防线：argon2id 密码哈希、登录限流（防撞库）、参数化 SQL（防注入）、
  `.gitignore` 覆盖 `*.db`/`.env`（防误提交）。
- 完整清单见 [PRD 07 §6](./07-非功能需求.md) 与 [TechDesign 03 §4](../TechDesign/03-服务端技术栈.md)。

## 16. R15 工期误判（**2026-08 新增**）

**风险形态**：此前的 V0 计划是"**2~4 周**"，但按 09 §6 的"晚 2 小时 + 周末半天"≈ **14 小时/周**计，
口径里还包含"dogfooding ≥ 2 周"——**留给开发的时间只有 0~28 小时**，
而要交付 12 项含 50 类知识库。**这是差 3~5 倍，不是"紧一紧"**。
真实后果是第一次就撞验收门禁，然后产生挫败感（正好命中 R7 倦怠）。

**对策**：

1. **新口径：3~4 周 @14h/周**，并显式写明前提；
2. V0 范围本身已收缩（去掉语音/ASR/推送/定时/部署，只保留账户 + 同步 + 管理 + 推算）；
3. **验收表做成可勾选的 7 条**（[08 §2.5](./08-MVP范围与版本规划.md)），每完成一条打勾，进度可见；
4. 若 3 周后仍未过半，**优先砍范围而不是延工期**（备选见 08 §2.3 的排除项）；
5. 每周只做一件事（08 §4）。

## 17. R16 SQLite 数据损坏或误删（**2026-08 新增**）

**风险形态**：V0 没有云端副本，`data/keepfresh.db` 是唯一数据源。
误删、磁盘故障、迁移脚本写错，都会一次性丢掉全部物资记录。

**对策**：

- **备份就是拷贝文件**：每周把 `data/keepfresh.db` 复制到另一个目录/网盘（写进 09 §6 周节奏）；
- 迁移脚本**必须包在事务里**，失败自动回滚；
- 破坏性变更走"加新列 → 双写 → 回填 → 停用旧列"四步，**禁止直接删列**；
- 软删除语义（`deleted_at`）保证用户误删可撤销；
- V1 公网化后此项升级为"需要自动备份与恢复演练"。
