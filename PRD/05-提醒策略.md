# 05 · 提醒策略

> 提醒是产品与用户唯一的"主动接触点"。做得好，用户觉得被照顾；做不好，用户关掉推送然后卸载。
> 本章定义：**何时提醒（时机矩阵）→ 怎么提醒（渠道）→ 说什么（生活化文案库）→ 怎么不烦人（防疲劳）→ 怎么闭环（处置动作）**。

---

## 1. 提醒类型与时机矩阵

### 1.1 四类提醒

| 类型 | 触发条件 | 用途 | 优先级 |
| ---- | ---- | ---- | ---- |
| **临期提醒** | 到期前 N 天（N 按保质期长度分档） | 给用户留出"用完它"的时间 | P0 |
| **开封计时提醒** | 开封后按 T1 倒计时 | 覆盖"开封后期限"场景 | P0 |
| **过期提醒** | 到期当天/次日 | 明确告知"别吃了"，降低误食风险 | P0 |
| **检查提醒** | 状态驱动品类（水果等）按"检查节奏"触发 | 帮用户"看一眼"实际状态，不承诺精确期限 | P0（V1，随生鲜果蔬最小版，见 04 §7） |

### 1.2 提前天数分档（按总保质期长度）

| 物品可用期限 | 首次提醒 | 二次提醒 | 说明 |
| ---- | ---- | ---- | ---- |
| ≤ 3 天（开封后生鲜） | 到期前 1 天 | 到期当天 | 短保品不啰嗦，提醒一两次即可 |
| 4~14 天 | 到期前 2 天 | 到期当天 | 主流食品档 |
| 15~90 天 | 到期前 5 天 | 到期前 1 天 | 中保品 |
| > 90 天 | 到期前 7 天 | 到期前 1 天 | 长保品（酱料、化妆品、药品） |
| 开封计时（T1 ≤ 3 天） | T1 的 50% 时点 | 到期前 6 小时 | 如辅食泥 48h → 24h 提醒一次、到期前提醒一次 |
| 检查提醒（状态驱动，水果） | 按检查节奏：第 2 天一次 + 窗口末一次 | 例：草莓窗口 1~2 天 → 第 2 天提醒"看一眼" |

### 1.3 合并策略（关键！）

- 同一天 ≥ 3 条提醒时，**合并为一条"今日临期汇总"**，避免轰炸：
  *"今晚冰箱有 4 样东西值得吃掉：牛奶（明天到期）、豆腐（明天）、面包（后天）、酸奶（后天）。"*
- 同一物品不重复提醒：已提醒过且用户未操作时，仅在"下次升级节点"（如临期→过期）再次提醒。

## 2. 提醒渠道

| 渠道 | 能力 | V1 决策 |
| ---- | ---- | ---- |
| 小程序订阅消息 | 一次性订阅（用户每次授权一次） | ⚠️ 订阅消息有次数限制，需在记录时引导"订阅本物品提醒" |
| 微信服务通知 | 依赖小程序订阅 | 同上 |
| App 推送（远期） | 稳定、可多次 | V2 转原生 App 后的主力渠道 |
| App 内横幅 | 打开 App 时首页顶部汇总 | **V1 兜底渠道**（即使订阅消息没发出去，打开 App 必见） |

> **V1 提醒策略的务实做法**：把"记录成功页"做成提醒授权的黄金时机——用户刚记录完，
> 弹出"要在这件东西快到期时提醒你吗？"（小程序一次性订阅）。同时首页常驻"临期/过期"横幅兜底。
> 完整策略与折中说明见 09-一人公司工作流 §3。

## 3. 提醒时机与频率

- **发送时间窗**：默认 08:00–21:00；可设置"免打扰时段"（如 12:00–14:00、22:00–08:00）。
- **推荐发送时刻**：晚间 18:30–20:30（下班回家做饭/整理时段）优先；早餐相关（牛奶、鸡蛋、面包）可选 08:00 档。
- **频率上限**：每用户每天最多 3 条单发提醒 + 1 条汇总；超出部分并入次日汇总。
- **沉默策略**：用户连续 3 次对某类提醒不点击 → 该类提醒降频（7 天一次），尊重用户注意力。

## 4. 生活化文案库（风格规范 + 示例）

> 风格三原则：**拟人化、给建议不给命令、用具体行动替代恐吓**。
> 禁止词表：库存告急、请立即处理、已过期禁止食用（可以更温和地说"建议不要再食用"）、红色感叹号。

| 场景 | 示例文案 | 备注 |
| ---- | ---- | ---- |
| 临期（食品） | "冰箱里的牛奶还有 2 天到期，早餐喝一杯刚刚好～" | 给具体行动 |
| 临期（生鲜） | "豆腐是今天到期的选手，晚上做个麻婆豆腐怎么样？" | 带菜谱联想，后续可接菜谱推荐（P2） |
| 临期（非食品） | "防晒霜开封快一年啦，防晒力会悄悄下降，这个夏天用完它吧。" | 知识科普感 |
| 过期 | "这盒酸奶已经悄悄过期了，是时候说再见啦（下次记得少买点哦）。" | 不指责 |
| 开封计时 | "辅食泥开封 24 小时了，请在明天中午前用完哦。" | 婴幼儿品类语气更认真但保持温和 |
| 汇总 | "今天冰箱有 4 样东西值得吃掉：……" | 合并消息 |
| 正向反馈 | "这个月你避免了 36 元浪费，够请自己喝一杯奶茶啦！" | 周报/月报 |
| 引导记录 | "买完东西，对它说句话，剩下的交给我～" | 空状态/新手引导 |

**文案管理**：文案集中存放于 `copywriting.json`（与知识库同机制远程更新），A/B 测试留到 V1.1。

## 5. 提醒 → 处置闭环（提醒的终点是行动）

每个提醒卡片/横幅必须提供**行动按钮**（见 03 F-08）：

```
[提醒卡片]
牛奶还有 2 天到期
[已用完] [已丢弃] [转赠] [延后 3 天]
```

- **已用完**：物品移入"已完成"，统计累加"避免浪费金额"（按品类单价参考值估算）。
- **已丢弃**：物品移入"已完成"，标记"丢弃"原因（浪费/变质），进入统计。
- **转赠**：标记转赠，可选"分享给家人"（P1 家庭共享后支持）。
- **延后 3 天**：适用于"我今晚就吃"但不想现在标记的情况；延后次数上限 2 次，防无限拖延。

## 6. 提醒有效性指标（与 01 §3.2 呼应）

| 指标 | 定义 | 目标 |
| ---- | ---- | ---- |
| 提醒送达率 | 送达 / 应发 | ≥ 90%（含 App 内横幅兜底） |
| 提醒点击率 | 点击卡片 / 送达 | ≥ 40% |
| 处置转化率 | 点击后完成处置 / 点击 | ≥ 70% |
| 48h 处置率 | 临期提醒后 48h 内被处置 / 临期提醒数 | ≥ 50% |
| 提醒关闭率 | 用户主动关闭推送的比例 | ≤ 15%（超过说明打扰过度） |
