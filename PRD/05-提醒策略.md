# 05 · 提醒策略

> 🛑 **【本章 V0 完全不生效】**（2026-08 范围收缩）
>
> **V0 不做任何提醒**——临期、过期、开封计时、检查提醒，以及页内横幅，**全部不做**。
> V0 是"物资总管"：只**算**不**推**（期限照常推算并在详情页展示依据，但不会到点打扰你）。
> 原因：提醒必须常开服务端才有意义，而 V0 跑在 `localhost`、不需要常开（见 [08-MVP范围与版本规划](./08-MVP范围与版本规划.md) §2.3）。
>
> **本章自 V1 起生效，内容保留不改写**——它是 V1 的核心资产，也是 V0 唯一的"预留接口"依据：
> V0 的 `Item` 模型会保留 `remindPolicy` / `windowStart` / `windowEndAt` 字段，并提供 `NoopNotifier`，
> 使 V1 加一个定时任务 + 推送发送即可，**不必改表、不必改协议**（08 §2.4）。
>
> 📖 阅读方式：本章所有时机矩阵、渠道决策、文案库、指标**均指 V1**；
> 文中的"V0 主力渠道""V0 务实做法"等字样是**历史口径，已作废**（已在正文逐处标注）。

> 提醒是产品与用户唯一的"主动接触点"。做得好，用户觉得被照顾；做不好，用户关掉推送然后卸载。
> 本章定义：**何时提醒（时机矩阵）→ 怎么提醒（渠道）→ 说什么（生活化文案库）→ 怎么不烦人（防疲劳）→ 怎么闭环（处置动作）**。
> ⚠️ 以上全部以"V1 有提醒"为前提；V0 阶段本章的**处置动作**（§5）是唯一在 V0 生效的部分，但它在 V0 由用户主动触发，不由提醒触发。

## 1. 提醒类型与时机矩阵

### 1.1 四类提醒

| 类型 | 触发条件 | 用途 | 版本 |
| ---- | ---- | ---- | ---- |
| **临期提醒** | 到期前 N 天（N 按保质期长度分档） | 给用户留出"用完它"的时间 | V1 |
| **开封计时提醒** | 开封后按 T1 倒计时 | 覆盖"开封后期限"场景 | V1 |
| **过期提醒** | 到期当天/次日 | 明确告知"别吃了"，降低误食风险 | V1 |
| **检查提醒** | 状态驱动品类（水果等）按"检查节奏"触发 | 帮用户"看一眼"实际状态，不承诺精确期限 | V1（随生鲜果蔬最小版，见 04 §7） |

> 📌 四类提醒**在 V0 全部不实现**（08 §2.3）。此处"版本"列取代原 P0 优先级列——原 P0/P1/P2 与版本号混用已废弃。

### 1.2 提前天数分档（按总保质期长度）

| 物品可用期限 | 首次提醒 | 二次提醒 | 说明 |
| ---- | ---- | ---- | ---- |
| ≤ 3 天（开封后生鲜） | 到期前 1 天 | 到期当天 | 短保品不啰嗦，提醒一两次即可 |
| 4~14 天 | 到期前 2 天 | 到期当天 | 主流食品档 |
| 15~90 天 | 到期前 5 天 | 到期前 1 天 | 中保品 |
| > 90 天 | 到期前 7 天 | 到期前 1 天 | 长保品（酱料、化妆品、药品） |
| 开封计时（T1 ≤ 3 天） | T1 的 50% 时点 | 到期前 6 小时 | 如辅食泥 48h → 24h 提醒一次、到期前提醒一次 |
| 检查提醒（状态驱动，水果） | 按检查节奏：第 2 天一次 + 窗口末一次 | 例：草莓窗口 1~2 天 → 第 2 天提醒"看一眼" |

### 1.3 合并策略（关键！）

- 同一天 ≥ 3 条提醒时，**合并为一条"今日临期汇总"**，避免轰炸：
  *"今晚冰箱有 4 样东西值得吃掉：牛奶（明天到期）、豆腐（明天）、面包（后天）、酸奶（后天）。"*
- 同一物品不重复提醒：已提醒过且用户未操作时，仅在"下次升级节点"（如临期→过期）再次提醒。

## 2. 提醒渠道

| 渠道 | 能力 | 阶段决策 |
| ---- | ---- | ---- |
| **第三方推送通道**（Bark / ntfy / 飞书机器人） | 服务端 HTTP 调用 → 系统级通知（走 APNs / 厂商通道） | **V1 主力渠道（起步方案）**：可靠、零推送开发；代价是用户需装一个中转 App（Bark 等） |
| **Web Push**（VAPID） | Service Worker 推送，不依赖第三方 App | **V1 产品化渠道**：⚠️ iOS 需 16.4+ **且已"添加到主屏幕"**、HTTPS、用户手势授权，三者缺一不可 |
| 页内横幅 | 打开网页（或后台标签页）时的首页汇总 | **V1 保留的兜底渠道**：展示"今日临期 X 件"与检查提醒，保证"打开必见"。⚠️ V0 也"打开才见"，但 V0 无提醒可言，不存在横幅 |
| 本地定时通知 | ⚠️ **浏览器不提供** | ❌ 不可用——这正是网页方案必须补推送通道的根本原因（TechDesign 12 §3） |

> **网页端提醒的现实（2026-08 平台迁移后重写）**：浏览器没有本地定时通知，页面一关就失去提醒能力。
> 因此**推送通道不是"多渠道兜底之一，而是网页端提醒的生命线"**——这也是放弃小程序、
> 并把"提醒可靠性"问题显式接管过来的原因（TechDesign 12 §3）。
>
> **V1 务实做法（原"V0 务实做法"，编号随范围收缩后移）**：服务端定时任务扫描提醒计划 → 一条 HTTP 请求把提醒推到手机；
> 页内横幅保证"打开就有"。**V1 产品化时切换为 Web Push**（不依赖第三方 App，可服务他人）。
>
> ⚠️ **原设计作废**：订阅消息配额账本、三类高价值提醒筛选、服务号订阅通知、双端去重
> ——这些机制的唯一目的是绕开小程序订阅限制，属于**平台税而非用户价值**，随小程序方案一并作废。
> 移动端原生（V2）恢复"本地定时通知 + 系统级推送"后，提醒可靠性才回到最优状态。
>
> 📌 **V0 定位**：以上渠道决策 V0 一律不实施。V0 只**保留接口**（`Notifier` + `NoopNotifier`），
> 保证 V1 接通道时不需要改后端协议与数据表（08 §2.4）。

## 3. 提醒时机与频率

- **发送时间窗**：默认 08:00–21:00；可设置"免打扰时段"（如 12:00–14:00、22:00–08:00）。
- **推荐发送时刻**：晚间 18:30–20:30（下班回家做饭/整理时段）优先；早餐相关（牛奶、鸡蛋、面包）可选 08:00 档。
- **频率上限**：每用户每天最多 3 条单发提醒 + 1 条汇总；超出部分并入次日汇总。
- **沉默策略**：用户连续 3 次对某类提醒不点击 → 该类提醒降频（7 天一次），尊重用户注意力。

## 4. 生活化文案库（风格规范 + 示例）

> 风格三原则：**拟人化、给建议不给命令、用具体行动替代恐吓**。
> 禁止词表：库存告急、请立即处理、已过期禁止食用（可以更温和地说"建议不要再食用"）、红色感叹号。

| 场景 | 示例文案 | 备注 |
| ---- | ---- | ---- |
| 临期（食品） | "冰箱里的牛奶还有 2 天到期，早餐喝一杯刚刚好～" | 给具体行动 |
| 临期（生鲜） | "豆腐是今天到期的选手，晚上做个麻婆豆腐怎么样？" | 带菜谱联想，后续可接菜谱推荐（V2） |
| 临期（非食品） | "防晒霜开封快一年啦，防晒力会悄悄下降，这个夏天用完它吧。" | 知识科普感 |
| 过期 | "这盒酸奶已经悄悄过期了，是时候说再见啦（下次记得少买点哦）。" | 不指责 |
| 开封计时 | "辅食泥开封 24 小时了，请在明天中午前用完哦。" | 婴幼儿品类语气更认真但保持温和 |
| 汇总 | "今天冰箱有 4 样东西值得吃掉：……" | 合并消息 |
| 正向反馈 | "这个月你避免了 12 件浪费，够给自己点个赞啦！" | 周报/月报；**件数版 V0 已有**（极简统计），**金额版（"避免了 36 元"）待单价体系校准后于 V2 启用**（03 F-11） |
| 引导记录 | "买完东西，对它说句话，剩下的交给我～" | V1 语音场景的新手引导；⚠️ V0 无语音，此文案 V0 不使用 |

**文案管理**：文案集中存放于 `copywriting.json`（与知识库同机制远程更新），A/B 测试留到 **V2**（原 V1.1，编号已废弃）。

## 5. 提醒 → 处置闭环（提醒的终点是行动）

> 📌 **V0 只保留本节的后半段**：提醒卡片与"延后 3 天"自 **V1** 起；但**处置动作本身在 V0 就有**——
> 用户在列表/详情里主动点"已用完 / 已丢弃 / 转赠"，且**5 秒内可撤销**（08 §2.2 处置）。
> 区别是：V0 的处置由**用户主动盘点**触发，不是由提醒触发。

每个提醒卡片/横幅必须提供**行动按钮**（见 03 F-08）：

```
[提醒卡片]
牛奶还有 2 天到期
[已用完] [已丢弃] [转赠] [延后 3 天]
```

- **已用完**：物品移入"已完成"，统计累加"避免浪费件数"（V0 已可统计件数，金额版见 03 F-11 / V2）。
- **已丢弃**：物品移入"已完成"，标记"丢弃"原因（浪费/变质），进入统计。
- **转赠**：标记转赠，可选"分享给家人"（**V2** 家庭共享后支持；原 P1，编号已废弃）。
- **延后 3 天**：适用于"我今晚就吃"但不想现在标记的情况；延后次数上限 2 次，防无限拖延。（**V1 起**，V0 无提醒卡片）

## 6. 提醒有效性指标（与 01 §3.2 呼应）

> 📌 **整节自 V1 起生效**：V0 没有提醒，下表**六个指标在 V0 全部无法度量**（01 §3.2 已把它们归入"V1 起可度量"组）。
> V0 对应位置的指标是"推算日期被手动修改的比例"与"在库/处置件数"，见 01 §3.2 A 组。

| 指标 | 定义 | 版本 | 目标 |
| ---- | ---- | ---- | ---- |
| 提醒送达率 | 送达 / 应发 | V1 | ≥ 90%（含页内横幅兜底） |
| 提醒点击率 | 点击卡片 / 送达 | V1 | ≥ 40% |
| 处置转化率 | 点击后完成处置 / 点击 | V1 | ≥ 70% |
| 48h 处置率 | 临期提醒后 48h 内被处置 / 临期提醒数 | V1 | ≥ 50% |
| **通知授权率** | 记录成功页授权成功 / 展示授权引导 | **V1** | ≥ 30%（2026-08 新增：提醒闭环的生死指标，低于则重设计授权时机） |
| 提醒关闭率 | 用户主动关闭推送的比例 | V1 | ≤ 15%（超过说明打扰过度） |
