## 二、产品速览（30 秒版）

- **产品名（暂定）**：保鲜盒（英文代号 KeepFresh）
- **一句话定位**：一款"生活化"的个人物品保质期管家——用语音/拍照 3 秒记录你买的东西，
  结合本地气候与物品特性推算"真实可用期限"，在合适的时间温柔地提醒你"该吃掉/用完它了"。
- **解决的核心问题**：记不住（买了就忘）、算不准（开封前后、夏冬气候不同）、提醒太粗暴（要么没有、要么吓人）。
- **北极星指标（暂定）**：**每周完成"记录→处置"闭环的物品数**（即用户记录后，在提醒驱动下真正用完/处理掉的数量）。
- **差异化**：语音优先录入 + 气候感知推算 + 生活化（不制造焦虑）的提醒，而非冷冰冰的"库存管理系统"。

## 三、关键决策速览（详见各文档）

| 决策点 | 结论 | 理由 |
| ---- | ---- | ---- |
| **版本号约定** | **只使用三档**：**V0**（=P0，当前开发）/ **V1**（=P1，提醒闭环 + 公网 + 移动端）/ **V2**（=P2，产品化）。原 V0.5 / V1.0 / V1.1 / V1.2 / V2.0 / P1.1 **一律废弃** | 此前 9 套编号混用，同一份文档集里 "V1.0" 有两套含义（08 §2 vs §3）。收敛后 `P0/P1/P2` 与版本一一映射（08 §1） |
| **V0 形态** | **电脑上的"物资总管"**：Vite+React 前端（PC 桌面浏览器）+ **本地 Node + SQLite 后端**；`pnpm dev` 一条命令起；**不部署、不要域名、不备案** | V0 要验证的是"**东西记得住吗、算得准吗**"，任何与之无关的工程复杂度都应排除（08 §2） |
| **账户与数据** | **用户名 + 密码**；**服务端 SQLite 为唯一权威**，账户下的物资通过服务端同步 | 有账户就必须有同步；单端使用不存在冲突，复杂度最低。原"端侧为权威/本地优先"会立刻带来离线队列与冲突合并（那是 V2 才需要的） |
| **平台** | **Web 优先**：V0 本地网页（PC）→ V1 公网 + 移动端 → V2 原生 App；**放弃微信小程序** | 提醒是核心价值，小程序订阅消息"一次授权=一条配额"扛不住；且用户无 Mac，Web 路线零 Mac 依赖（TechDesign 12） |
| **V0 不做的能力** | ❌ 一切提醒　❌ 一切推送通道　❌ 语音与 ASR　❌ PWA/移动端适配　❌ 公网部署/域名/备案（未决策）　❌ 定时任务/Cron　❌ 天气 API　❌ 拍照/OCR　❌ 家庭共享　❌ 金额统计 | **"保留接口，不写实现"**：REST 契约 `/api/v1/*`、提醒字段、`Notifier`/`VoiceInput` 接口在 V0 就冻结，V1 加移动端时不改协议（08 §2.3–§2.4） |
| 保质期数据 | 自建**品类基线知识库**（V0 做 **50 类**常用品，V1 扩到 100+，V2 到 200+） | 长尾品类由"自定义模板"兜底，不追求一开始全 |
| 生鲜果蔬（水果等） | **状态驱动模型，V0 即纳入最小版**（典型窗口 + 检查节奏字段，**V0 只存不推**） | 水果是最高频购买品类，最小版成本低；复杂增强（成熟度档/多模态/切开重算）不可精确预测，留待数据校准（V2） |
| 气候因子 | **V0 手动三档**（夏季/潮湿/梅雨）+ **未设置时 `k=0.9` 保守值**；V1 接入天气 API 自动判断 | 不依赖任何第三方 API；⚠️ 原设计"不确定档"没有系数，等于默认 1.0，**信息最少的用户反而拿到最长期限**，与保守原则相反（上一轮审查 P1-10，已在 04 §4.1 修正） |
| 提醒渠道 | **V1 起**：Web Push（VAPID，iOS 需 16.4+ 且"添加到主屏幕"）+ 页内横幅兜底；V1 早期可先用第三方通道（Bark/ntfy）跑通 | 浏览器没有可靠的本地定时通知，页面关闭即失去提醒能力——推送是网页端提醒的生命线（05 §2 / TechDesign 12 §3）。⚠️ 但**推送并非可靠到可以当承诺**：iOS 订阅会静默失效且权限拒绝后无法程序化重申请，因此产品承诺应为"**打开时一定会看到**" |
| 统计口径 | V0 只统计**避免浪费件数**（3 个数字，不做图表）；金额版待单价体系校准后启用（**V2**） | qty 单位体系（盒/箱/瓶/袋）未校准前金额不可信（03 F-11） |
| 商业模式 | 免费 + 订阅（高级功能：家庭共享/多端同步/深度统计）——**整体属 V2** | 个人工具付费意愿低，但"为家人省心"可撬动付费；⚠️ Web 端收款方式与合规属 V1 阶段重估项（10 §1.1） |
