## 二、产品速览（30 秒版）

- **产品名（暂定）**：保鲜盒（英文代号 KeepFresh）
- **一句话定位**：一款"生活化"的个人物品保质期管家——用语音/拍照 3 秒记录你买的东西，
  结合本地气候与物品特性推算"真实可用期限"，在合适的时间温柔地提醒你"该吃掉/用完它了"。
- **解决的核心问题**：记不住（买了就忘）、算不准（开封前后、夏冬气候不同）、提醒太粗暴（要么没有、要么吓人）。
- **北极星指标（暂定）**：**每周完成"记录→处置"闭环的物品数**（即用户记录后，在提醒驱动下真正用完/处理掉的数量）。
- **差异化**：语音优先录入 + 气候感知推算 + 生活化（不制造焦虑）的提醒，而非冷冰冰的"库存管理系统"。

## 三、关键决策速览（详见各文档）

| 决策点 | 结论 | 理由 |
| ---- | ---- | ---- |
| 平台 | 先做**微信小程序**验证，后做 App | 一人公司冷启动成本最低、分享传播容易；App 推送更强，留到有留存证据后再做 |
| 语音识别 | 微信同声传译插件（**开工前验证可用性**，voice 层抽象可替换）+ 腾讯云 ASR 备选 | 免费额度内零成本；插件存在账号主体门槛与过审风险，B 方案兜底（09 §3.2） |
| 保质期数据 | 自建**品类基线知识库**（先 50 类常用品，逐步扩到 200+） | 长尾品类由"自定义模板"兜底，不追求一开始全 |
| 生鲜果蔬（水果等） | **状态驱动模型，V1 以"最小版"纳入**（典型窗口 + 检查提醒，与其他品类同等级）；状态档/多模态等复杂增强 P2 | 水果是最高频购买品类，最小版成本低；复杂增强不可精确预测，留待数据校准 |
| 提醒渠道 | 订阅消息**仅临期/过期/开封三类**（一次性配额账本）+ App 内横幅兜底（含检查提醒，双端去重）+ **服务号订阅通知（V1.2）** | 一次性授权是最大短板：配额用在刀刃上 + 多渠道兜底（05 §2） |
| 气候因子 | V1 用**用户手动选择气候档**（首记后引导，可跳过）；V1.2 接入天气 API 自动判断 | 冷启动阶段避免对第三方 API 的依赖；不阻塞首记 |
| 数据存储 | **本地优先**，默认不上传照片与记录；导出端侧完成 | 隐私是信任资产，也是差异化卖点 |
| 统计口径 | V1 只统计**避免浪费件数**，金额版待单价体系校准后启用（P1.1+） | qty 单位体系（盒/箱/瓶/袋）未校准前金额不可信（03 F-11） |
| 商业模式 | 免费 + 订阅（高级功能：多端同步/家庭共享/深度统计） | 个人工具付费意愿低，但"为家人省心"可撬动付费；⚠️ 个人主体不能开通微信支付，主体资质 V1.1 末决策（10 §1.1） |

## 五、如何使用本 PRD

1. **第一次读**：按 01 → 02 → 03 的顺序读，建立"为谁、做什么"的整体认知。
2. **开发前**：开发读 03 + 04 + 05 + 06 + 07，测试读 03（验收标准）。
3. **每次迭代前**：打开 08（MVP 范围）与 10（假设验证清单），用数据决定下一步做哪个功能。
4. **写周报/复盘时**：对照 09（一人公司工作流）中的节奏与指标。
