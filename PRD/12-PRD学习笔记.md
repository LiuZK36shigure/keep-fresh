## 1. 这份 PRD 的结构逻辑（一张图记住）

```
为什么做（01 概述：问题/定位/指标）
  → 为谁做（02 用户：画像/场景/用户故事）
  → 做什么（03 功能 + 06 信息架构与流程）
  → 怎么做对（04 推算规则 + 05 提醒策略 + 07 非功能）
  → 先做多少（08 MVP 与版本）
  → 怎么活下来（09 工作流 + 10 商业增长 + 11 风险）
```

PM 的思维模型：**问题 → 用户 → 方案 → 验证 → 迭代**，这份 PRD 只是把这个模型"写下来"了。

| 章节 | 训练的能力 | 面试可讲的点 |
| ---- | ---- | ---- |

## 3. 一人公司 vs 大厂 PM 的区别（理解这个，作品集才有灵魂）

| 维度 | 大厂 PM | 一人公司（本 PRD 视角） |
| ---- | ---- | ---- |
| 决策依据 | 数据、上级、跨部门博弈 | **用户反馈 + 自己的时间成本** |
| 文档读者 | 研发、设计、运营、老板 | 自己（和未来的自己） |
| 失败代价 | 项目被砍，换项目 | 项目就是你的心血 |
| 优势 | 资源多 | **离用户近、决策快、试错成本低** |
| 核心能力 | 推动力、影响力 | 全栈自驱 + 克制 + 持续验证 |

> 一人公司的 PRD 有一个大厂 PRD 没有的功能：**它是你的"外置大脑"**——
> 你中断一个月后靠它恢复上下文，你倦怠时靠它提醒自己"当初为什么做"。

## 4. 这份 PRD 里"刻意设计"的细节（学习点）

1. **北极星指标的选择**：没有用"日活"，而用"每周完成记录→处置闭环的物品数"——因为它同时度量使用频率与价值完成度（01 §3.2）。
   ⚠️ V0 阶段"提醒驱动"那一桶恒为 0，**这个指标在 V0 只用来校验闭环是否跑通，不用来判断留存**（01 §3.2 说明）。
2. **语音解析用规则而非大模型**：**V1 起才有的能力**（V0 不做语音，08 §2.3）。V1 求"可预期、可纠错、零成本"，而非"聪明"——技术选型服从一人公司现实（03 F-01）。
3. **提醒的"防轰炸合并"**：一天 ≥3 条合并为 1 条汇总——反直觉但正确：提醒的目标是行动不是存在感（05 §1.3）。**属 V1**（V0 整章不做提醒）。
4. **付费墙放在"家庭共享"**：不是功能最多的位置，而是**付费意愿最强**的位置（10 §1.1）。**属 V2**（V0/V1 不收费）。
5. **风险章排在商业章之后、全文最后**：阅读顺序上"先学会走路再担心摔跤"，但内容上风险意识贯穿始终。

## 5. 你的下一步行动清单（按顺序，2026-08 按新的 V0 重排）

> 📌 **先说清 V0 的边界**：**V0 不做提醒、不做语音、不做推送，只做"物资总管"**——
> 账户 → 手动表单录入 → 三层推算 → 完整管理视图（分组/排序/筛选/搜索）→ 详情 → 处置 + 5 秒撤销 → 极简统计（3 个数字）。
> 换句话说，V0 是一次**"回归"**：把所有花活（语音、提醒、推送、公网）全部拿掉，
> 只回答最初那个问题——**"我记录的数据与推算出来的期限，到底可不可信？"**（08 §2.5 / §3）
> 这个问题的答案才是 V1 提醒闭环的地基；地基不牢，提醒做得再好也没人信。
>
> 阶段一~三仍然值得做（它们和 V0 的能力无关，只和"你想清楚没有"有关），**阶段四是唯一直接对应代码的部分**。

### 阶段一：验证假设（1~2 周，不改代码）
- [ ] 按 02 章附录访谈提纲，找 5~8 位真实用户聊"上次扔掉过期食品"的经历；
- [ ] 下载 3 个竞品 App 试用，记录"在哪一步我放弃了"；
- [ ] 把访谈原话补充进 02 章的画像与场景（PRD 立刻变"活"）。
      ⚠️ 注意：访谈验证的是 **V1** 的假设（语音/提醒/留存）。V0 阶段这些都不是必做项，
      但访谈能帮你确认"盘点"这个 V0 主场景（02 §3 场景 3）是不是真痛点。

### 阶段二：原型验证（1~2 周）
- [ ] 用 Figma 按 06 章线框画 **3 个 V0 页面**：**管理视图（列表：分组/排序/筛选/搜索）+ 物品详情（含推算依据）+ 录入表单**；
      ⚠️ 原清单是"首页/语音页/确认页"——**V0 没有语音页**（语音属 V1），把精力放在"列表好不好扫、表单填得快不快"上；
- [ ] 用"纸原型 + 桌面录像"让 3 个朋友走一遍"**在电脑上盘点一次冰箱**"流程（登录 → 找临期 → 看依据 → 标记用完），
      测**耗时与卡点**；
- [ ] 更新 03 章的验收标准（把原型测试发现的问题写进去）。

### 阶段三：数据准备（可以现在就开始，V0 直接要用）
- [ ] 按 04 章字段结构，先整理 **50 类**你日常生活中最常见的品类基线（每类写清依据）——**V0 的知识库就是 50 类**（08 §2.2）；
      没有数据基础，推算引擎就没有可校准的输入；
- [ ] 起草生活化文案库 20 条（05 §4 风格）——⚠️ 05 章整体属 **V1**，但 V0 也需要"推算依据文案"（08 §2.2 推算模块）；
- [ ] 这 50 类 + 20 条文案，就是 V0 知识库（`shelf_rules.json` + `copywriting.json`）的"种子"。

### 阶段四：开发启动（V0 = 前端 + 本地后端 + 账户与同步）
- [ ] 对照 08 章 V0 清单搭骨架：**前端** `npm create vite`（Vite + React + TypeScript，**只面向 PC 桌面浏览器**）；
      **后端** 本地 **Node + Hono + SQLite**，与前端**同仓**，`pnpm dev` **一条命令同时起**；
      **账户与同步**：用户名 + 密码（argon2id）+ 会话 token + **数据按账户隔离**，**服务端 SQLite 为唯一权威**；
      （⚠️ 已删去原"服务端用 Cloudflare Workers"一行——**V0 不碰服务器部署**，不买服务器、不需要域名与备案，见 08 §2.1 / §2.3）；
- [ ] 每完成一个功能，用 03 章对应 GWT 自测；
- [ ] **V0 的验收不用拉内测群**：先自己真实使用 ≥ 2 周、库存 30 件以上并保持更新，跑通 08 §2.5 的 7 条验收；
      **拉 20 人内测群是 V1 的事**（V0 没有公网产品，别人也用不上）。

> **一句话**：V0 做完之后，你手上应该有一个"**自己每天都愿意打开的物资清单**"，
> 而不是一个"功能很多但自己不用"的 demo。这也是判断 V0 成败的唯一标准。

## 6. 学习资源推荐

- **书**：《人人都是产品经理》（苏杰）、《启示录：打造用户喜爱的产品》（Marty Cagan）、《精益创业》（Eric Ries）——一人公司必读。
- **概念**：北极星指标（North Star Metric）、Jobs to be Done（用户不是买产品，是"雇用"产品完成任务）、
  用户故事与验收标准、AARRR 漏斗、MVP 与"最小可行"的边界。
- **实践**：多做"访谈 → 写 PRD → 做原型 → 找人测"的循环，比读十本书都有效；本 PRD 的每次迭代记录就是你的 PM 作品集。

## 7. 给这份 PRD 的"毕业标准"

当你能做到以下三点，这份 PRD 就从"作业"变成了"作品"：

1. 你能**不看文档**向别人讲清：为谁、解决什么、凭什么赢、先做什么；
2. 你能用**访谈与数据**证明或推翻至少 1 条假设（10 §4 清单）；
3. 你能**砍掉**一个自己很喜欢的功能，并说出理由。

> 祝你在"把想法变成产品"的路上走通第一个闭环。PRD 是起点，不是终点——去验证吧。
