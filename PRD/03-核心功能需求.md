# 03 · 核心功能需求

> 本章是给开发/测试看的"功能规格说明书"：每个功能模块给出**功能描述、交互要点、优先级、验收标准**。
> 验收标准采用 Given-When-Then 与检查清单两种写法，开发自测与测试用例都以此为准。
>
> 功能优先级定义：**P0** = MVP 必须有，缺了产品闭环不成立；**P1** = V1.1，增强体验；
> **P2** = 远期，验证后决定。

## 2. 详细需求

### F-01 语音录入（核心中的核心）

**功能描述**：用户在任意页面点击/长按"语音大按钮"，说出如"牛奶，今天买的，一箱"，系统
语音识别后自动解析出【品类】【数量】【购买日期】【是否开封】，进入确认页，用户确认或修改后保存。

**交互流程**：见 06-信息架构与核心流程 §4.1。

**解析规则（V1 规则版，不依赖大模型）**：

| 用户说的话 | 解析结果 |
| ---- | ---- |
| "牛奶，今天买的" | 品类=鲜牛奶，数量=1，购买日=今天，开封=否 |
| "酸奶 三盒 上周二买的" | 品类=酸奶，数量=3，购买日=上周二，开封=否 |
| "那个苹果 昨天买的" | 品类=苹果，数量=1，购买日=昨天 |
| "鸡蛋开封了" | 品类=鸡蛋，数量=1，购买日=未知（提示补充），开封=是 |
| 无法识别品类 | 提示"没听清是什么～试试说'牛奶 今天买的'"，给出热门品类快捷选择 |

**验收标准**：

- GWT-01：Given 用户在语音页，When 说出"牛奶，今天买的"且网络正常，Then 3 秒内展示确认页，品类=鲜牛奶、数量=1、日期=今天、开封=否，且**无需用户手动修改即可保存**。
- GWT-02：Given 确认页展示中，When 用户说"不对，是昨天买的"，Then 购买日期改为昨天（支持二次语音纠错）。
- GWT-03：Given 语音内容不含日期（如只说"牛奶"），When 进入确认页，Then 默认购买日=今天，并标注"默认今天，可修改"。
- GWT-04：Given 语音识别失败或无网络，When 用户提交，Then 降级为手动表单（F-02），不阻塞记录。
- 性能：从按下按钮到确认页出现 ≤ 3 秒（含识别）。
- 准确率：常用 50 类品类的解析正确率 ≥ 85%（内测统计，见 01 §3.2）。

### F-02 手动录入（兜底）

**功能描述**：表单录入：品类（搜索/热门列表）→ 数量 → 购买日期 → 开封状态 → 存储位置 → 备注 → 保存。

**验收标准**：

- GWT-05：Given 用户从任意入口进入手动录入，When 完成必填项（品类、数量、购买日期）并点保存，Then 物品出现在列表中，推算到期日正确展示。
- GWT-06：Given 用户未填写开封状态，When 保存，Then 默认"未开封"且详情页可随时改为"已开封"（改后立即按开封规则重新推算）。

### F-03 快捷模板（一键再买）

**功能描述**：历史记录过的物品自动生成模板；在语音页/记录页顶部展示"常用品"（如牛奶、鸡蛋、面包），点一下即按上次参数记录（默认今天购买）。

**验收标准**：

- GWT-07：Given 用户记录过 ≥3 次"鲜牛奶"，When 打开记录页，Then "常用品"区展示"鲜牛奶"快捷按钮。
- GWT-08：Given 用户点击快捷按钮，When 无修改直接确认，Then 记录成功且总步骤 ≤ 2 步。

### F-04 拍照记录（P1）

**功能描述**：拍照/相册上传物品照片（包装、小票、开封状态），照片归档在物品详情中；V1 不强制识别，仅存档；P2 可做 OCR 识别包装日期（见 F-14 远期）。

**验收标准**：

- GWT-09：Given 用户在记录页选择拍照，When 拍摄完成，Then 照片附加到该物品记录，缩略图展示在列表与详情页。
- GWT-10：Given 用户删除物品，When 确认删除，Then 照片一并删除（或明确提示保留）。
- 隐私：照片**默认仅存本地**（见 07 非功能需求）。

### F-05 保质期自动推算

**功能描述**：保存记录时，系统按【品类基线 → 开封状态 → 气候因子】三层规则自动计算"预计可用到期日"，并展示推算依据（"未开封鲜牛奶冷藏 7 天 × 夏季高温系数 0.8 ≈ 6 天"）。

**规则细节**：见 04-保质期推算规则.md。

**验收标准**：

- GWT-11：Given 用户保存"鲜牛奶，今天，未开封，冷藏"，When 推算完成，Then 到期日 = 今天 + 7（夏季为 +6 或 +5，取决于气候档），且展示依据文案。
- GWT-12：Given 推算完成，When 展示到期日，Then 页面上明确标注"估算值"及"可修改"入口，不得让用户误以为是包装标注。
- GWT-13：Given 用户所在城市开启自动气候（P1+），When 城市进入高温/梅雨档，Then 后续新记录的推算自动应用对应系数。

### F-06 用户修正反馈回路

**功能描述**：用户可修改到期日、开封日期、品类；修改行为（如"实际提前坏了"）记录为一次"校准样本"。

**验收标准**：

- GWT-14：Given 用户将某物品到期日提前 2 天并选择原因"实际已变质"，When 保存，Then 系统记录校准样本（用于后续规则调优），且不影响其他物品。
- GWT-15：Given 用户修改开封状态为"已开封"，When 保存，Then 到期日立即按"开封后期限"重新推算并更新提醒计划。

### F-07 提醒（临期/过期/开封计时/检查）

**功能描述**：按 05-提醒策略 的规则生成提醒：临期提醒（到期前 N 天）、过期提醒、开封计时提醒、
检查提醒（状态驱动品类如水果，按检查节奏触发）。渠道：App 内横幅 + 系统推送 / 小程序订阅消息（V1 以小程序订阅消息为主，见 09 §3 平台决策）。

**验收标准**：

- GWT-16：Given 某物品到期日为 D，当 D-3 天 08:00~21:00 窗口内，Then 用户收到"临期提醒"，文案符合生活化风格库。
- GWT-17：Given 用户当天已有 ≥3 条提醒，When 触发新提醒，Then 合并为一条"今日临期汇总"（防提醒轰炸）。
- GWT-18：Given 用户在某物品提醒卡片上点"已用完"，Then 该物品移入"已完成"，且当天不再收到该物品的任何提醒。
- GWT-19：Given 用户关闭全部推送，When 打开 App，Then 首页顶部展示"你有 X 件物品临期/过期"横幅，保证 App 内可见。

### F-08 提醒卡片内处置

**功能描述**：提醒卡片/通知提供动作按钮：【已用完】【已丢弃】【转赠】【延后 3 天】，点击后无需进入 App 即可完成处置。

**验收标准**：

- GWT-20：Given 用户在推送卡片点击"已用完"，When 操作成功，Then 物品状态更新、统计"避免浪费金额"累加，且 3 秒内反馈成功。

### F-09 物品列表与管理（P1）

**功能描述**：首页 Tab"我的物品"：按【位置分组】（冰箱冷藏/冷冻/储物柜/药箱/化妆台）+ 排序（默认到期日升序）+ 搜索 + 筛选（临期中/已过期/已开封）。

**验收标准**：

- GWT-21：Given 列表加载，When 用户切换分组/排序，Then 1 秒内完成渲染，且筛选条件记忆上次选择。
- GWT-22：Given 存在已过期物品，When 打开列表，Then 过期物品置顶并以温和样式标识（不闪烁、不用红色警示大叹号）。

### F-10 物品详情（P1）

**功能描述**：展示照片、品类、数量、购买日、开封日、推算到期日与推算依据、历史处置记录。

**验收标准**：

- GWT-23：Given 打开详情，When 数据完整，Then 展示推算依据（"基线 7 天 × 夏季系数 0.8"），点击可展开规则说明。

### F-11 统计与成就（P1）

**功能描述**：月度报告：记录数、用完数、丢弃数、**避免浪费金额估算**（按品类均价）、连续记录天数、徽章（如"连续 7 天记录"）。

**验收标准**：

- GWT-24：Given 本月有 5 件物品标记"已用完"，When 打开统计页，Then 展示"本月避免浪费约 X 元"（按品类默认单价估算，标注"估算"）。
- GWT-25：Given 用户连续记录 7 天，When 打开统计页，Then 展示"记录达人"徽章。

### F-12 家庭共享（P1）

**功能描述**：创建"家庭空间"，通过邀请码/微信邀请成员；所有成员共享物品库与提醒（提醒按成员设置分发）。

**验收标准**：

- GWT-26：Given 用户创建家庭空间并邀请成员，When 成员接受邀请，Then 双方可见同一物品库，任一成员处置物品后状态实时同步。
- GWT-27：Given 两个成员同时编辑同一物品，When 后保存者提交，Then 以"后保存者 + 合并备注"策略处理，不互相覆盖丢失（V1.1 简化：后保存者覆盖并提示）。

### F-13 设置

| 子项 | 说明 | 优先级 |
| ---- | ---- | ---- |
| 气候档位 | 手动选择：城市 / 南方-潮湿 / 北方-干燥 / 夏季高温开关；V1.2 支持自动 | P0 |
| 提醒时间窗 | 默认 08:00-21:00 可调，支持免打扰时段 | P0 |
| 推送开关 | 总开关 + 按提醒类型（临期/过期/开封）细分 | P0 |
| 隐私设置 | 照片仅本地 / 允许云备份（默认关）、导出数据、彻底删除账号 | P0 |
| 品类知识库更新 | 展示"知识库版本"，支持拉取更新 | P1 |

## 3. 全局交互与体验要求

1. **记录永远一步可达**：首页底部中央为常驻"语音大按钮"，任何页面 1 次点击可达（呼应 US-01 的黄金时刻）。
2. **可撤销**：删除物品后 5 秒内可撤销（Toast + 撤销按钮）。
3. **空状态设计**：无记录时展示插画 + 引导话术（"买完东西，对它说句话吧～"），并给 3 个示例物品一键添加（用于新用户体验闭环，见 06 §4.4）。
4. **文案一致性**：所有提醒与反馈文案必须使用"生活化文案库"（见 05 §4），禁止出现"库存告急""已过期，请立即处理"等惊吓式表达。

## 4. 埋点需求（一人公司也要埋点）

| 事件 | 触发 | 用途 |
| ---- | ---- | ---- |
| record_voice_start / record_voice_success / record_voice_fail | 语音录入各阶段 | 语音漏斗分析 |
| record_save | 记录保存 | 记录量、北极星分子 |
| estimate_modified | 用户修改推算日期 | 推算准确率（01 §3.2） |
| remind_received / remind_click | 提醒到达/点击 | 提醒有效性 |
| item_disposed(type=used/discard/gift) | 处置动作 | 北极星、浪费金额 |
| invite_sent / invite_accepted | 家庭邀请 | 裂变验证 |

> 埋点平台选择（一人公司）：初期用小程序自带数据分析 + 自建极简事件日志（本地 + 可选上报），
> 不做复杂用户画像系统。
