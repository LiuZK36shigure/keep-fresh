## 1. 信息架构（IA · V0）

```
保鲜盒（Web，PC 桌面浏览器）
│
├── 登录 / 注册                     ← V0 入口（无会话时强制跳转）
│
├── 物资列表（V0 主界面 ★）          ← 默认落地页
│   ├── 分组标签：冷藏 / 冷冻 / 储物柜 / 药箱 / 化妆台 / 其他
│   ├── 工具条：排序（到期日/购买日/录入时间）+ 筛选（全部/未处置/临期中/已过期/已开封）+ 搜索框
│   ├── 物资卡片：品类名 · 数量 · 状态标签 · 到期日 · [已用完] [已丢弃]
│   └── 卡片 → 物品详情
│
├── 新增 / 编辑物资（表单）           ← V0 的记录入口（V1 起增加语音与拍照入口）
│   ├── 品类（搜索 + 热门 + 常用）
│   ├── 数量 / 购买日 / 开封状态 / 存储位置 / 备注
│   └── 保存后显示推算结果与依据
│
├── 统计（V0 极简）
│   └── 三个数字：在库件数 / 本月处置件数 / 本月避免浪费件数
│
└── 设置
    ├── 气候档位（夏季 / 潮湿 / 梅雨 三个开关）
    ├── 默认存储位置
    ├── 知识库版本
    ├── 修改密码 / 登出
    └── 关于（免责声明）

【V1 起新增】提醒横幅 · 语音录入 · 拍照记录 · 统计图表 · 提醒设置 · 通知授权管理
【V2 起新增】家庭空间 · 成员管理 · 共享物品库
```

**导航设计（V0）**：顶部或侧边导航 = 【物资列表】【统计】【设置】。
**没有底部 Tab、没有居中语音大按钮**——那是移动端的形态，V1 再做。
V0 是**桌面优先**的布局（宽屏表格/卡片混排），但组件按响应式写，避免 V1 重写。

## 2. 物品生命周期状态模型（**V0 完整生效**）

```
        ┌──────────┐
        │  已记录   │
        │ (未开封)  │
        └────┬─────┘
             │ 用户标记"开封了"
             ▼
        ┌──────────┐
        │  已开封   │  （从开封日起按 T1 重新计时）
        └────┬─────┘
             │
    ┌────────┼──────────────────┐
    ▼        ▼                  ▼
┌────────┐ ┌────────┐      ┌─────────┐
│ 临期中  │ │ 已过期  │      │ 处置完成 │
└────────┘ └────────┘      │用完/丢弃 │
                           │ /转赠    │
                           └─────────┘

【V1 起】"延后 3 天"作为**自环**加在临期中/已过期上（推迟提醒，不改状态）
```

> ⚠️ **两处修正（上一轮审查 P2 #19/#20）**：
> ① 原状态表把"已记录（未开封）"写成"**无提醒**"，与 05 §1.2 的「>90 天 → 到期前 7 天提醒」冲突。
> 正确表述是：**已记录状态下，到期前会按 05 §1.2 的分档进入"临期中"**。
> ② 原状态机图把"延后"画成从"已开封"**指回"已记录"**，等于一次状态回退，
> 与 `TechDesign 04` 的「**延后不改状态、只推迟提醒**」矛盾。**已改为自环**，且"延后"属 V1。

状态说明：

| 状态 | 定义 | 触发动作 |
| ---- | ---- | ---- |
| 已记录（未开封） | 记录保存，未开封 | 按 05 §1.2 分档，到期前进入"临期中"（**V1 起有主动提醒**；V0 仅在列表中以状态标签体现） |
| 已开封 | 用户标记开封 | **从开封日按 T1 重新计时**（不是在 T0 基础打折） |
| 临期中 | 距到期 ≤ 提前提醒天数 | V0：列表状态标签 + 置顶；V1：生成临期提醒 |
| 已过期 | 超过推算到期日 | V0：列表置顶（温和样式）；V1：生成过期提醒 |
| 处置完成 | 用完 / 丢弃 / 转赠 | 移入历史，计入统计；**5 秒内可撤销**（软删除） |

> ⚠️ **实现要点**：`临期中 / 已过期 / 已开封` **不是数据库里的状态**，
> 而是**服务端按当前日期推导出的展示态**（见 [TechDesign 04 §3.5](../TechDesign/04-数据模型与存储.md)）。
> 这样"今天到期"会随时间自动变化，**V0 不需要任何定时任务**。

## 3. 关键流程

### 3.1 流程一：表单录入（**V0 主流程**）

```
[物资列表] 点「＋ 新增物资」
      │
      ▼
[表单页] 品类（输入"奶" → 搜索到"鲜牛奶"，并显示保存建议）
        数量（默认 1）
        购买日（默认今天，不得晚于今天）
        开封状态（默认未开封；选"已开封"则开封日默认今天）
        存储位置（默认取设置里的 defaultStorage）
        备注（可选）
      │ 点「保存」
      ▼
[服务端] 鉴权 → Zod 校验 → 调 core/engine 推算 → 落库 → 返回完整记录
      │
      ▼
[详情页] 展示：预计到期 7 天后（高温潮湿季 → 4 天）
        ⓘ 依据：未开封冷藏 7 天 × 气候 0.64 ≈ 4 天  [修改到期日]
```

**设计要点**：
- **推算在服务端完成**，前端只展示返回的 `reasonText`（不在前端重算，见 01 ADR-02）；
- **依据必须可见**——"信任感来源于可解释"，这是 V0 唯一需要"让用户夸"的点；
- **V1 起**，本流程前面会多一个语音入口（`→ 语音识别 → 预填本表单`），
  **表单本身不变**——这就是"保留接口"的价值。

### 3.2 流程二：管理物资（**V0 主流程**）

```
[物资列表]
   ├─ 切换分组（冷藏 / 冷冻 / …）        → 查询参数 storage=
   ├─ 排序（到期日升序默认）              → sort=expireAt&order=asc
   ├─ 筛选（临期中 / 已过期 / 已开封）     → status=
   ├─ 搜索（品类名 / 备注）               → q=
   └─ 卡片操作
        ├─ [已用完] / [已丢弃]  → POST /items/:id/dispose → 卡片消失 + 统计更新 + 5 秒撤销
        └─ 点卡片              → 物品详情
```

**设计要点**：**筛选与排序全部下推到 SQL**，前端只负责把条件拼进 URL 并记忆上次选择。
500 条数据下列表渲染 ≤ 1 秒（GWT-21）。

### 3.3 流程三：拍照记录（**V1 起**）

```
记录页 → 拍照按钮 → 拍摄/相册选图
   → 快速裁剪（可选）→ 附加到"待确认物品"表单
   → 与手动录入一样进入确认 → 保存
```

### 3.4 流程四：提醒 → 处置（**V1 起**）

> ⏸ **V0 没有提醒**。V0 的处置入口在列表卡片与详情页；V1 会在提醒通知上再加一个入口。
> ⚠️ 且 **V1 的推送通知无法渲染自定义动作按钮**（iOS 平台限制），
> 现实做法是"点通知 → 打开网页 → 落地页预置该物品的处置卡片"。详见 [03 F-08](./03-核心功能需求.md)。

```
[V1] 推送/横幅：'牛奶还有 2 天到期'
      │ 点击 → 打开网页（落在该物品的处置卡片上）
      ├─ 已用完 → 物品完成 + 件数统计 + 撤销机会(5s)
      ├─ 已丢弃 → 同上（计入浪费统计）
      ├─ 转赠   → 标记转赠（V2 可分享给家人）
      └─ 延后3天 → 重排提醒（不改状态，上限 2 次）
```

### 3.5 流程五：新用户引导（V0）

```
欢迎页（一句话价值 + 插画）
   → 注册（用户名 + 密码）
   → 空状态引导：'把买回来的东西记下来吧～'
      + 3 个示例物品一键添加（让用户 30 秒内看到列表有内容）
   → 气候档位：「顺带一问」（可跳过；跳过即"不确定"档，取保守系数 0.9）
   → 进入物资列表
```

**设计要点**：新用户必须在第一次会话内**完成一次记录**，否则大概率流失。
气候档案**不阻塞首次记录**——推算在"不确定"档下照常工作（按 0.9 保守估算），
首记完成率优先于推算精度（对应 04 §4.2）。
