# 10 · 商业模式与增长

> 📌 **V0 生效范围（2026-08 范围收缩）**：**本章整体属于 V2，V0 不适用**，内容保留作为远期资产。
>
> - **§1 商业模式**：变现设计（Freemium、付费墙）**自 V2 起**生效。V0 **无收费、无主体资质、无收款**，也**不需要**——
>   V0 是跑在你自己电脑上、只有你一个账户的自用工具（08 §2.1）。**"免费版包含什么"在 V0 就是"全部功能"**。
> - **§2 冷启动**：**V0 阶段完全不存在**——没有公网产品、没有域名、没有可被访问的地址，谈不上"0 → 100 用户"。**自 V1 起生效**。
> - **§3 关键指标漏斗**：同 §2，**自 V1 起生效**（V0 没有"曝光"这一环）。
> - **§4 假设验证清单**：V0 只能验证其中一小部分（见该节说明），**H1/H3/H4/H5 的时间点集中在 V1/V2**。
>
> **V0 只保留本章的【商业设计意图】**。V0 范围见 [08-MVP范围与版本规划](./08-MVP范围与版本规划.md) §2、§3。
>
> 一人公司的商业原则（2026-08 修订）：**变现设计从 V0 起就埋好钩子（接口与账户体系先留好），但 V0/V1 阶段不碰收费**——
> 先验证"数据与推算是否可信"（V0），再验证"提醒有没有用"（V1），最后才验证付费（V2）。

> 本章回答两个问题：**怎么赚钱（不亏钱地活下去）**、**怎么让第一批用户来（冷启动）**。
> ⚠️ 这两个问题在 V0 都还不成立：V0 不赚钱、不拉人，只服务你自己（见上方说明）。

## 1. 商业模式

### 1.1 主模式：Freemium（免费 + 订阅）

> 📌 **本节自 V2 起生效**；V0 无免费/高级之分（全部功能都是你自己的），V1 也暂不收费。

| 版本 | 价格（暂定） | 包含 |
| ---- | ---- | ---- |
| 免费版 | 0 元 | **语音记录、推算、提醒、处置闭环、单设备、基础统计** |
| 高级版（订阅） | 6 元/月 或 38 元/年（参考定价，需验证） | 多设备同步、**家庭共享（核心卖点）**、深度统计与月度报告、知识库优先更新、无广告（如未来有） |

> ⚠️ **怎么读这张表**：它描述的是 **V2 阶段**的产品形态——那时 V1 的能力（语音、提醒）已经存在，
> 所以免费版里出现它们是**正常的**，不是"把 V1 能力写进了 V2 的表"。
> 对照关系：**免费版里"语音记录/提醒"来自 V1，"推算/处置/基础统计"来自 V0，"高级版"整列来自 V2。**
>
> **V0 没有免费/高级之分**（全部功能都是你自己的，也没有第二个人能用）；
> **V1 也不收费**（PRD 10 §1 的开头原则：先验证价值，再验证付费）。

**为什么订阅而不是买断**：持续的成本在知识库维护与服务器；订阅制与"持续被提醒"的服务属性匹配。
**为什么家庭共享放付费墙**：为家人管理是强付费动机（02 画像 B），也是天然裂变场景。

> **主体与支付约束（2026-08 平台迁移后重估，随商业模式一并归入 V2）**：
> - 原"个人主体小程序不能开通微信支付 / iOS 小程序虚拟支付受限"的约束**随小程序方案作废**；
> - Web 端收款需另行评估：面向中国大陆个人开发者的可选路径（第三方聚合收款/买断制/赞助）均需合规确认，
>   列为 **V2 阶段重估项**（原"V1 阶段重估项"，因 V0 不收费、V1 不收费而后移）；
> - **决策点后移**：原"V1.1 末决定是否注册个体工商户"（服务号 + 微信支付依赖）**取消**（编号已废弃）；
>   何时需要经营主体，取决于 V2 选定的收款方式。⚠️ V0/V1 阶段**不需要任何主体资质**。

### 1.2 备选/远期变现

- **买断制 + 内购**（若订阅转化率 < 3% 再评估）；
- **品牌合作**（食品品牌"临期食谱"内容合作，V2+，不影响用户体验为前提）；
- **明确不做**：❌ 卖用户数据（信任是产品的命根子，见 07 §1）；❌ 广告轰炸（与"生活化不打扰"的品牌相悖）。

### 1.3 成本结构（呼应 09 §5）

> 📌 **V0 的成本结构完全不同且更简单（2026-08 范围收缩）**：V0 跑在 `localhost`，**没有服务器、没有公网、没有第三方账号**，
> 现金成本 **≈ 0 元**，唯一成本是你的时间（08 §2.1 / 09 §6 的 14 小时/周口径）。下表是 **V1 公网化之后**的口径。

- 可变成本 ≈ 0（Serverless 免费额度）；
- 单人时间成本 = 最大成本 → **定价只需覆盖时间价值即可盈利**。

## 2. 冷启动（0 → 100 用户）

> 🛑 **本节在 V0 不适用（2026-08 范围收缩）**：
> V0 **没有公网产品**——跑在自己的电脑上、只有 `localhost`、不买服务器、不需要域名与备案（08 §2.1），
> 因此**"曝光 → 打开 → 拉人"这条链在 V0 根本不存在**。**本节自 V1 起生效**（V1 才部署公网并开始面对他人）。
>
> **V0 的"用户"就是你自己**：V0 的增长任务不是拉新，而是**把库存在 30 件以上、连续两周保持更新**——
> 这既是 08 §2.5 的 V0 完成定义，也是 V1 冷启动唯一可信的素材来源（"我自己用了两周，推算准不准我最清楚"）。
> 本章 §2、§3 的**渠道与打法全部保留**，只把过期的版本号与已作废的平台渠道改写到新口径，供 V1 直接取用。

### 2.1 冷启动渠道优先级

> 📌 **本节自 V1 起**。⚠️ 表中"即时通讯熟人网络"一行由原"微信熟人网络"改写而来——微信内的分享/引流路径随小程序方案作废，改走通用群聊与朋友圈；**V0 阶段本节全部不执行**。

| 渠道 | 打法 | 版本（原 P0/P1 优先级） |
| ---- | ---- | ---- |
| 小红书 | 内容型冷启动：发"冰箱临期拯救计划""梅雨季食物保存指南""一人食冰箱复盘"等图文/短视频，评论区引流 | V1（发布即启动） |
| 豆瓣小组 | 极简生活、收纳、一人食小组发体验帖（先当真实用户分享，再带产品） | V1 |
| **即时通讯熟人网络**（群聊/朋友圈） | 内测群 20 人 = 第一批种子用户；邀请家人共用的场景做裂变（**V2** 家庭共享上线后） | V1（裂变部分依赖 V2） |
| 内容直链 / 网页 SEO | 网页版最大红利：**内容里直接放链接**，点开即用、无需安装、无需审核；关键词改为网页 SEO + 内容标题 | V1 |
| 知乎/公众号 | 长文：食物浪费数据 + 亲测体验（引 01 §1.1 的数据） | V2（原 P2，编号口径统一） |

### 2.2 内容资产化（一人公司的最优杠杆）

- 每次迭代的"数据发现"（如"内测用户平均每周避免浪费 12 件"）本身就是内容素材；
- 建立**每周 1 篇**的固定输出节奏（写文 1 小时，AI 辅助）；
- 让产品自带传播点：**V2** 的"成就分享卡片"（F-11）就是为小红书场景设计的（原 V1.1，编号已废弃）。
  ⚠️ V0 的统计只有 3 个数字、**不做图表、不做分享卡片**（08 §2.2 统计模块）。

### 2.3 增长飞轮（愿景）

```
用户记录物品 → 避免浪费(省到钱) → 成就感 → 分享(卡片/家人邀请)
      ↑                                          │
      └──────── 新用户记录 ← 内容种草 ← 传播 ←──┘
```

## 3. 关键指标漏斗（Growth Funnel）

> 📌 **本节自 V1 起生效**：漏斗的第一环是"曝光（小红书/搜索）"，而 **V0 没有任何曝光来源**（无公网产品，见 §2 说明）。
> V0 的等价"漏斗"只有一条：**登录 → 录入 → 管理 → 处置**（08 §2.5 第 6 条的闭环校验）。

```
曝光(小红书/搜索) → 打开网页(无需安装) → 完成首次记录 → 次日打开 → 周活跃 → 处置闭环 → 邀请/付费
     ↓                 ↓             ↓            ↓          ↓         ↓
   内容CTR         首启转化率      首记完成率     次日留存    次周留存   周处置率   邀请率/付费率
  (≥5%参考)       (≥60%参考)      (≥70%参考)    (≥40%参考)  (≥25%参考) (≥50%参考) (≥15% / ≥3%参考)
```

**漏斗分析节奏**：每周复盘只盯"最差的下一环"——例如"打开多但首记少"，就优化新用户引导（06 §3.4），而不是做新功能。
⚠️ V0 阶段没有跨用户数据可分析，**这条节奏从 V1 起执行**；V0 的"每周复盘"是自用记录（09 §4）。

## 4. 假设验证清单（本 PRD 最重要的"待办"）

> ⚠️ **V0 只能验证"一半的 H2"（2026-08 范围收缩）**：V0 没有语音（H1）、没有分享/统计图表（H3）、
> 没有真实用户与公网（H4）、没有 A/B 能力（H5）——**这四条在 V0 无法验证**。
> V0 唯一能验证的是 **H2 的推算部分**：用**手动气候档**检查"夏天牛奶坏得快"这类结论是否符合常识与自己的经验（08 §2.5 第 4 条）。
> 下表"验证时间点"已按 **V0 / V1 / V2** 新口径改写（原 V1.1/V1.2/P1.1 编号已废弃）。

| 编号 | 假设 | 验证方法 | 验证时间点 | 若证伪 |
| ---- | ---- | ---- | ---- | ---- |
| H1 | 语音记录显著降低记录门槛，驱动留存 | 内测分流对比（语音 vs 手动） | **V1** 内测第 3 周 | 强化确认页/快捷模板，弱化语音优先级 |
| H2 | 气候修正对用户有感知价值 | V0：手动档自用核对推算结果；V1：内测问卷 + 推算详情页点击率 | **V0**（自用核对）→ **V1**（用户感知） | 降级为"可选增强"，主推基础提醒 |
| H3 | "避免浪费"反馈（V1 件数；**金额版 V2**）能驱动分享 | 分享卡片点击/截图率 | **V2**（原 V1.1；分享卡片本身属 V2） | 换成就感形式（徽章/报告） |
| H4 | 家庭共享是付费点 | **V2** 家庭空间内测 + 付费意愿访谈 | **V2**（原 V1.1） | 换付费点（多端同步/统计） |
| H5 | 生活化文案优于功能化文案 | 文案 A/B | **V1**（原 V1.2；A/B 需有真实流量，05 §4） | 保留功能性表达，生活化仅用于品牌层 |

> **使用方法**：每完成一个版本，回到这张表勾选/更新。这张表就是你的"PM 学习成果"最硬的证据。
> ⚠️ 注意 H5 与 A/B 测试**都依赖 V1 的流量**：V0 阶段这份清单里只有 H2 的前半段可以动手。
