# 09 · 一人公司工作流

> 一人公司（One-Person Company / Solo Founder）不是"一个人干五个人的活然后累死"，
> 而是**用工具和取舍把五个角色的工作量压缩到一个人的带宽内**。
> 本章回答：一人公司怎么把"保鲜盒"从 PRD 变成产品，再变成能自转的小生意。

---

## 1. 一人公司的本质

```
传统公司：产品(PM) + 设计 + 前端 + 后端 + 运营 + 客服 + 增长 = 7 人
一人公司：1 人 × 7 个角色，靠三样东西补足人力：
          ① 成熟的平台与工具（Web/PWA、Serverless、AI）
          ② 极致的范围克制（08 章：每周只做一件事）
          ③ 数据与自动化（埋点替代运营，配置化替代客服）
```

**三条铁律**：

1. **先有收入信号，再扩投入**：V1 的目标是验证"有人愿意用"，不是验证"功能多"；
2. **所有知识写下来**：代码注释、PRD、运营手册都在仓库里——你生病/忙考试时，项目不会停摆；
3. **可配置 > 可开发**：改一个 JSON 能解决的事，绝不上线一个新版本。

## 2. 一人公司的角色 × 工具替代表

| 角色 | 传统做法 | 一人公司做法 | 工具 |
| ---- | ---- | ---- | ---- |
| 产品经理 | 需求文档 + 评审会 | 本 PRD + 每周数据复盘 + 用户访谈 | 本仓库 / 飞书文档 |
| 设计师 | 设计团队 | AI 生成插画与图标 + 自研轻量组件 + 简洁风格克制 | Figma、AI 绘图、**自建设计令牌**（CSS 变量，见 TechDesign 01 §2） |
| 前端开发 | 前端工程师 | **Web 前端（Vite + React + TS）** + 自研轻量组件 + **AI 辅助编码**（70% 代码由 AI 起草） | VS Code、Cursor/Claude Code |
| 后端开发 | 后端团队 | **Serverless 免运维**：定时任务 + 推送发送 + ASR 代理 + 静态托管 | Cloudflare Workers / 轻量服务器 |
| 测试 | QA 团队 | 验收标准即测试用例（03 章 GWT）+ 内测群 20 人当"众测" | 自测 + 内测群 |
| 运营 | 运营团队 | 小红书/豆瓣内容输出 + 内测群维护 | 小红书、微信群 |
| 客服 | 客服团队 | 配置化 FAQ + 内测群直接回答（早期用户少，人工够用） | 群 + 飞书机器人 |

## 3. 关键技术决策（一人公司视角）

### 3.1 平台选型：Web 优先（2026-08 迁移决策）

| 维度 | 微信小程序 | **Web（选定）** | 原生 App |
| ---- | ---- | ---- | ---- |
| 提醒可靠性 | ❌ 一次性订阅配额；长期订阅仅公共类目 | ⚠️ 需补推送通道（**V1**：第三方通道 → Web Push） | ✅ 本地定时通知最优 |
| 开发条件 | 微信开发者工具 | ✅ **Windows 即可**（无 Mac 也能开发与使用） | ❌ iOS 需 macOS |
| 开发成本 | 一套代码双端 | ✅ 一套代码；**V0 先只做 PC 桌面浏览器**，V1 才做移动端 | 双端 + 上架合规 |
| 分发/内测 | ✅ 扫码即用 | ✅ 无需安装、无需审核；**但公网发布要面对备案（V1，见 11 R13）** | ❌ 商店审核 + 备案 |
| 系统能力 | ❌ 无小组件、无系统 ASR | ⚠️ 受限（浏览器无可靠的本地定时通知） | ✅ 最完整 |
| 逻辑层复用 | TS（转 Flutter **不可复用**） | ✅ 纯 TS `packages/core` → 未来 RN/Expo **直接复用** | — |

**决策（2026-08 范围收缩后）**：
**V0 = 电脑上的"物资总管"**——Vite + React（PC 桌面浏览器）+ **本地 Node + SQLite** 后端，
`pnpm dev` 一条命令起；**有账户、有同步、有完整管理视图，但不做提醒/语音/推送/部署**。
V1 才部署公网 + Web Push + 语音 + 移动端；V2 视数据决定是否转 React Native 原生 App。

- **放弃小程序的原因**：提醒是产品的核心价值，而小程序订阅消息"一次授权 = 一条配额"、
  长期订阅仅向公共服务类目开放，扛不住高频提醒；为绕开它设计的"配额账本 + 三类筛选 + 服务号补充"
  属于**平台税，不是用户价值**。
- **接受 Web 的代价**：浏览器没有可靠的本地定时通知 → 必须补推送通道（TechDesign 12 §3）；
  获客摩擦高于小程序（V1 产品化时面对，V0 不涉及）。
- **V0 不做部署的额外红利**：**不需要域名、不需要备案、不需要任何第三方账号**——
  把合规与运维这两个不确定性整体推迟到你有真实用户之后（见 11 R13）。
- 完整迁移方案见 [TechDesign 12-Web优先方案](../TechDesign/12-Web优先方案（平台迁移决策）.md)。

### 3.2 语音识别选型（**V1 起**）

> ⏸ **V0 不做语音**（V0 用表单录入，见 03 F-02）。本节为 V1 保留。

| 方案 | 成本 | 结论 |
| ---- | ---- | ---- |
| **前端归一化 + MediaRecorder 录音 + 服务端云 ASR 代理**（腾讯云一句话识别 / 讯飞） | 腾讯云 **5,000 次/月免费**，之后 3.20 元/千次；讯飞默认 500 次/日免费，之后 0.005 元/次 | **V1 首选 ✅**（密钥留服务端，不下发客户端） |
| 浏览器原生 Web Speech API | 免费 | ❌ **不可选**：iOS Safari 支持不可靠 |
| 自建 ASR | 高 | 不做 |

> ⚠️ **V1 实现前必须知道（技术核实后确认）**：Chrome 的 `MediaRecorder` 产出
> `audio/webm;codecs=opus`，**讯飞（只收 pcm/wav/speex）与腾讯云（不收 WebM 容器）都不接受**。
> **必须在浏览器端 `decodeAudioData` 归一化为 16k 单声道 WAV 后再上传**——
> 服务端转码这条路在 Workers 上堵死（无子进程，且 ffmpeg.wasm 不被支持）。
> 详见 [TechDesign 12 §6.1](../TechDesign/12-Web优先方案（平台迁移决策）.md)。
>
> 另：`VoiceInput` 接口与 `packages/core/parser/` 目录在 **V0 就留空占位**，
> 这样 V1 加语音时**表单本身不用改**，只是在它前面多一个入口。

### 3.3 天气/气候数据

- **V0**：**用户手动气候档案**（夏季 / 潮湿 / 梅雨三个开关；全关 = "不确定"档，取保守系数 0.9），零依赖；
- **V1**：接入天气 API 自动判断，失败自动回退手动档。
  > ⚠️ 原表述"和风天气**免费版**"**已过时**：和风天气现在全量按量计费，
  > "免费开发者订阅"不存在；实际是"天气和基础服务"分组**每月前 50,000 次 = 0 元**
  > （本项目用量远在额度内 ✓）。另需注意：**开发者类型选定后不可更改**。

### 3.4 数据与后端（2026-08 范围收缩后重写）

- **服务端 SQLite 是唯一权威**：物品明细、账户、设置全部存在服务端（`data/keepfresh.db`），
  **前端不持有权威副本，也不做本地缓存**——"账户下的物资通过服务器同步"；
- **后端就是本机的一个 Node 进程**：`pnpm dev` 与前端一起起；
  **不部署、不买服务器、不需要域名与备案、不需要第三方账号**；
- **V0 后端职责只有四件事**：① 鉴权与归属校验　② 物资增删改查　③ 调用 `packages/core` 推算引擎　④ 配置加载与校验；
- **V0 没有的东西**：定时任务、推送发送、ASR 代理、埋点接收、云端存储——**这些全是 V1**；
- ⚠️ "微信云开发（依赖微信身份 openid）"与"Cloudflare Workers"**都随范围收缩作废**（V1 部署时再选）。

> **为什么这样更省**：V0 的后端不需要"常开"（你自己开电脑就是常开），
> 也不需要任何运维——**这正是把"必须常开"这个约束推迟到 V1 的价值**。

## 4. 研发工作流（AI 辅助版）

```
需求（PRD 仓库）→ 原型（Figma 低保真，复用 06 章线框）
   → 开发（AI 起草代码 → 人工 review → 自测对照 03 章 GWT）
   → 内测（**直接发网页链接**，无需安装、无需审核 + 群里收反馈 + 修复）
   → 数据（埋点 → 每周复盘 → 更新 PRD 假设）
```

**AI 使用要点**：

1. 让 AI 按"03 章验收标准"写代码，验收标准就是 Prompt 的需求规格；
2. 让 AI 生成品类知识库初稿（给它 04 章的字段结构），**人工必须逐条审核**（食品安全！）；
3. 让 AI 生成生活化文案初稿，**人工挑选 20%** 进文案库——AI 文案容易"过甜"，需要人味；
4. 代码全部提交 Git（含 PRD 文档），AI 改坏了随时回滚。

## 5. 成本预算

### 5.1 V0（当前）：**0 元**

| 项目 | 成本 | 说明 |
| ---- | ---- | ---- |
| 前端 / 后端 | **0 元** | 都在你自己的电脑上跑 |
| 数据库 | **0 元** | SQLite，单文件，无需安装服务 |
| 域名 / 备案 / HTTPS 证书 | **0 元** | V0 跑 `localhost`，**三样都不需要** |
| 第三方账号（云服务 / ASR / 推送） | **0 元** | **一个都不需要** |
| 设计素材 | 0 ~ 50 元 | AI 生成 + 免费图标库 |
| **合计** | **0 元**（可选 0~50 元素材） | — |

> **V0 唯一的大额成本：你自己的时间**（3~4 周 @14h/周）。所以范围克制（08 章）比省钱更重要。

### 5.2 V1 起（公网化后才产生）

| 项目 | 月成本 | 说明 |
| ---- | ---- | ---- |
| **域名 + ICP 备案** | ≈ 5 元 + 时间成本 | 60 元/年；**备案是 V1 的第一件前置决策**（见 11 R13） |
| **境内轻量服务器**（若走备案路径） | 24 ~ 100 元 | 备案要求境内接入；**Cloudflare 无法备案** |
| 或：Workers Paid（若走境外路径） | ≈ 36 元（$5） | 免费版的 CPU 10ms / 子请求 50 是硬墙，撑不住一轮推送 |
| HTTPS 证书 | 0 元 | Let's Encrypt / Cloudflare 自动签发 |
| 语音识别（云 ASR） | 0 ~ 几十元 | 腾讯云 5,000 次/月免费，之后 3.20 元/千次；讯飞 500 次/日免费 |
| 推送通道 | 0 元 | Bark / ntfy 免费；Web Push 用 VAPID 自签，无第三方费用 |
| 营销 | 0 ~ 200 元 | 小红书投流可选，初期不投 |
| **合计** | **≈ 30 ~ 300 元/月** | — |

> 说明：原"微信小程序认证 / 主体资质（服务号、微信支付）"成本随小程序方案作废；
> **Apple 开发者 $99/年与上架合规成本推迟到 V2**（原生 App 阶段）。
>
> ⚠️ **成本论证的一处修正**（上一轮审查）：原表把"0 元 Cloudflare 免费版"与"60 元 VPS"并列成二选一，
> 但**免费版有 CPU 10ms / 子请求 50 的硬墙**（跑不完一轮推送），
> 而 **$5 的 Workers Paid（≈36 元）就把子请求提到 10,000**——
> **"0 元"是有工程代价的 0 元，"60 元 VPS"的性价比论证是反的**。详见 [TechDesign 12 §5.2](../TechDesign/12-Web优先方案（平台迁移决策）.md)。

## 6. 时间管理（学生/兼职场景）

| 现实约束 | 对策 |
| ---- | ---- |
| 白天上课/上班 | 固定"晚上 2 小时 + 周末半天"开发窗口，雷打不动 |
| 考试周/项目周 | 知识库与文案可远程配置 → 功能不会坏；PRD 写清 → 回来能续上 |
| 精力波动 | 每周只做一件事（08 §4）；状态差的日子做"低脑力活"（文案、知识库、回复内测群） |
| 孤独感/失去动力 | 内测群用户的正反馈就是"团队"；每周发一次"进度播报"到群里 |

## 7. 用户反馈闭环（一个人的客服体系）

```
内测群（20~50 人）
  ├─ 每周五发版 → 群里发"本周更新了什么"（生活化口吻）
  ├─ 用户报 Bug → 飞书表格登记 → 按 P0/P1/P2 排期
  ├─ 用户提需求 → 记入 Backlog（08 §5）→ 每周复盘时用数据裁决做不做
  └─ 每周 2~3 个深度访谈（语音/视频 20 分钟）→ 更新 02 章画像与场景
```

**需求裁决规则**（防止被用户带偏）：一个需求满足以下至少两条才做——
① ≥ 3 个用户独立提出；② 与北极星指标（01 §3.2）相关；③ 实现成本 ≤ 2 天。

## 8. 一人公司每周复盘模板

```
本周指标：记录量 __ / 提醒点击率 __ / 处置率 __ / 留存 __
本周做了：____
数据说明了：____
用户说了：____（引用 1~2 条原话）
下周只做：____（1 件事）
PRD 更新：____（改了哪个假设/哪个优先级）
```

> 复盘记录放在仓库 `docs/reviews/` 下，这是你作为 PM 最重要的"数据资产"。
