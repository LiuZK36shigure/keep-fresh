# 09 · 一人公司工作流

> 一人公司（One-Person Company / Solo Founder）不是"一个人干五个人的活然后累死"，
> 而是**用工具和取舍把五个角色的工作量压缩到一个人的带宽内**。
> 本章回答：一人公司怎么把"保鲜盒"从 PRD 变成产品，再变成能自转的小生意。

---

## 1. 一人公司的本质

```
传统公司：产品(PM) + 设计 + 前端 + 后端 + 运营 + 客服 + 增长 = 7 人
一人公司：1 人 × 7 个角色，靠三样东西补足人力：
          ① 成熟的平台与工具（微信小程序、Serverless、AI）
          ② 极致的范围克制（08 章：每周只做一件事）
          ③ 数据与自动化（埋点替代运营，配置化替代客服）
```

**三条铁律**：

1. **先有收入信号，再扩投入**：V1 的目标是验证"有人愿意用"，不是验证"功能多"；
2. **所有知识写下来**：代码注释、PRD、运营手册都在仓库里——你生病/忙考试时，项目不会停摆；
3. **可配置 > 可开发**：改一个 JSON 能解决的事，绝不上线一个新版本。

## 2. 一人公司的角色 × 工具替代表

| 角色 | 传统做法 | 一人公司做法 | 工具 |
| ---- | ---- | ---- | ---- |
| 产品经理 | 需求文档 + 评审会 | 本 PRD + 每周数据复盘 + 用户访谈 | 本仓库 / 飞书文档 |
| 设计师 | 设计团队 | AI 生成插画与图标 + 开源组件库 + 简洁风格克制 | Figma、AI 绘图、微信设计规范 |
| 前端开发 | 前端工程师 | 小程序原生 + 组件库 + **AI 辅助编码**（70% 代码由 AI 起草） | 微信开发者工具、Cursor/Claude Code |
| 后端开发 | 后端团队 | **Serverless 零运维**：云函数 + 云数据库 + 云存储 | 微信云开发 / 阿里云函数计算 |
| 测试 | QA 团队 | 验收标准即测试用例（03 章 GWT）+ 内测群 20 人当"众测" | 自测 + 内测群 |
| 运营 | 运营团队 | 小红书/豆瓣内容输出 + 内测群维护 | 小红书、微信群 |
| 客服 | 客服团队 | 配置化 FAQ + 内测群直接回答（早期用户少，人工够用） | 群 + 飞书机器人 |

## 3. 关键技术决策（一人公司视角）

### 3.1 平台选型：先小程序，后 App

| 维度 | 微信小程序 | 原生 App | 结论 |
| ---- | ---- | ---- | ---- |
| 分发成本 | 低：扫码即用、无需审核商店 | 高：双端上架、证书费 | 小程序 ✅ |
| 开发成本 | 一套代码双端 | 两套或跨端框架 | 小程序 ✅ |
| 推送能力 | ⚠️ 订阅消息一次性授权，次数受限（服务号订阅通知 V1.2 补充触达） | ✅ 稳定推送 | App 胜，但可后补 |
| 家庭分享 | ✅ 微信天然好友关系 | 需自建邀请体系 | 小程序 ✅ |
| 冷启动 | ✅ 微信群/朋友圈传播 | 应用商店冷启动难 | 小程序 ✅ |

**决策**：**V1 用微信小程序**（配合"App 内横幅兜底 + 订阅消息三类高价值"的提醒策略），
**V2 用数据说话**：若访谈证实"推送限制是用户流失主因"，再上 Flutter 版 App（代码可复用逻辑层）。
补充：V1.2 接入**公众号服务号订阅通知**作为订阅消息的补充触达（需企业/个体户主体，见 §5）。

### 3.2 语音识别选型

| 方案 | 成本 | 结论 |
| ---- | ---- | ---- |
| 微信同声传译插件 | 免费额度内 | V1 首选 ✅（**但需先验证**，见下） |
| 腾讯云 ASR | 按量付费（低用量月成本几十元内） | 备选（WechatSI 不可用时的 B 方案） |
| 手机系统语音（快捷指令） | 免费 | 远期备选 |
| 自建 ASR | 高 | 不做 |

> **开工前验证门禁（2026-08 新增）**：WechatSI 插件的可用性因账号主体而异（有开发者反馈个人主体
> 添加后无法过审/搜不到插件）。**写任何代码之前**，用真实 AppID 完成三项验证（半天）：
> ① 插件市场能否搜到并添加；② 体验版能否正常识别；③ 能否通过小程序审核。
> 同时 `services/voice` 按"可替换接口"实现（TechDesign 02 §4），B 方案腾讯云 ASR 按 feature flag 切换。

### 3.3 天气/气候数据

- V1：**用户手动气候档案**（见 04 §4.2），零依赖；
- V1.2：免费天气 API（和风天气免费版等），失败自动回退手动档。

### 3.4 数据与后端

- 记录数据**本地优先**（07 §1），同步仅用于多设备（P1）；
- 云端仅：知识库 JSON、文案 JSON、匿名埋点、家庭共享数据（P1 后）；
- 全部使用微信云开发（Serverless），初期**月成本 ≈ 0 元**。

## 4. 研发工作流（AI 辅助版）

```
需求（PRD 仓库）→ 原型（Figma 低保真，复用 06 章线框）
   → 开发（AI 起草代码 → 人工 review → 自测对照 03 章 GWT）
   → 内测（20 人微信群：发版 + 收集反馈 + 修复）
   → 数据（埋点 → 每周复盘 → 更新 PRD 假设）
```

**AI 使用要点**：

1. 让 AI 按"03 章验收标准"写代码，验收标准就是 Prompt 的需求规格；
2. 让 AI 生成品类知识库初稿（给它 04 章的字段结构），**人工必须逐条审核**（食品安全！）；
3. 让 AI 生成生活化文案初稿，**人工挑选 20%** 进文案库——AI 文案容易"过甜"，需要人味；
4. 代码全部提交 Git（含 PRD 文档），AI 改坏了随时回滚。

## 5. 成本预算（月）

| 项目 | 月成本 | 说明 |
| ---- | ---- | ---- |
| 微信小程序认证 | ≈ 0 元（个人主体免费/企业 300 元/年） | 个人主体可发布 V1，但**个人主体不能开通微信支付、不能注册服务号** |
| 主体资质 | 0 元（个人）→ 执照免费 + 认证 300 元/年（个体工商户） | **V1.1 末决策**（2026-08 修订）：服务号订阅通知（V1.2）与订阅支付（V1.2）共同依赖；若届时维持个人主体，则变现改买断/品牌合作（10 §1.2） |
| 云开发 Serverless | 0 ~ 30 元 | 免费额度内够用（V1） |
| 语音识别 | 0 元（WechatSI 免费额度）→ 腾讯云 ASR 按量（备选） | 先验证再定（§3.2） |
| 天气 API | 0 元 | 免费版 |
| 设计素材 | 0 ~ 50 元 | AI 生成 + 免费图标库 |
| 营销 | 0 ~ 200 元 | 小红书投流可选，初期不投 |
| **合计** | **≈ 0 ~ 300 元/月** | 一人公司可以"零成本"启动 |

> 唯一的大额潜在成本：**你自己的时间**。所以范围克制（08 章）比省钱更重要。

## 6. 时间管理（学生/兼职场景）

| 现实约束 | 对策 |
| ---- | ---- |
| 白天上课/上班 | 固定"晚上 2 小时 + 周末半天"开发窗口，雷打不动 |
| 考试周/项目周 | 知识库与文案可远程配置 → 功能不会坏；PRD 写清 → 回来能续上 |
| 精力波动 | 每周只做一件事（08 §4）；状态差的日子做"低脑力活"（文案、知识库、回复内测群） |
| 孤独感/失去动力 | 内测群用户的正反馈就是"团队"；每周发一次"进度播报"到群里 |

## 7. 用户反馈闭环（一个人的客服体系）

```
内测群（20~50 人）
  ├─ 每周五发版 → 群里发"本周更新了什么"（生活化口吻）
  ├─ 用户报 Bug → 飞书表格登记 → 按 P0/P1/P2 排期
  ├─ 用户提需求 → 记入 Backlog（08 §5）→ 每周复盘时用数据裁决做不做
  └─ 每周 2~3 个深度访谈（语音/视频 20 分钟）→ 更新 02 章画像与场景
```

**需求裁决规则**（防止被用户带偏）：一个需求满足以下至少两条才做——
① ≥ 3 个用户独立提出；② 与北极星指标（01 §3.2）相关；③ 实现成本 ≤ 2 天。

## 8. 一人公司每周复盘模板

```
本周指标：记录量 __ / 提醒点击率 __ / 处置率 __ / 留存 __
本周做了：____
数据说明了：____
用户说了：____（引用 1~2 条原话）
下周只做：____（1 件事）
PRD 更新：____（改了哪个假设/哪个优先级）
```

> 复盘记录放在仓库 `docs/reviews/` 下，这是你作为 PM 最重要的"数据资产"。
