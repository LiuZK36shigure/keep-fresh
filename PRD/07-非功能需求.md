# 07 · 非功能需求（NFR）

> 📌 **V0 生效范围（2026-08 范围收缩，本章已按 V0 重写）**：
> - **V0 的数据边界变了**：不再是"本地优先（端侧为权威）"，而是**服务端 SQLite 为唯一权威**——
>   但 V0 的服务端**就跑在你自己电脑上**，所以隐私论证仍然成立（网络不出 localhost）；
> - **V0 的第一号安全问题不是"云端泄露"，而是"越权访问"**（§6.1）；
> - **V0 不做离线**（§3）：服务端为权威，断开后端即不可用——**不要假装可用**；
> - **V0 的兼容性目标是 PC 桌面浏览器**（§4），移动端属 V1。
>
> V0 范围见 [08-MVP范围与版本规划](./08-MVP范围与版本规划.md) §2。
> **版本号**：**V0**（=P0，当前）/ **V1**（=P1）/ **V2**（=P2）。

> 非功能需求决定用户"用起来舒不舒服、敢不敢用"。对个人数据类产品，**隐私与安全是第一位**。

---

## 1. 数据边界（V0）

### 1.1 V0 的实际边界

| 数据 | 存放位置 | 说明 |
| ---- | ---- | ---- |
| 物资明细（品类/数量/日期/开封/存储/备注） | **服务端 SQLite**（你自己的机器） | V0 唯一权威数据源；按 `user_id` 隔离 |
| 账户 | 服务端 SQLite | 密码只存 **argon2id 哈希** |
| 会话 | 服务端 `sessions`（存 token 哈希） | 登出即吊销 |
| 知识库 / 文案 | `config/*.json`（Git 管理） | 不含任何用户数据 |
| 日志 | 服务端本地文件 | **禁止记录密码、token、备注全文** |
| 照片 / 语音 | **V0 没有** | 属 V1 |

> ⚠️ **这条隐私论证是"V0 限定"的**：数据在你自己的机器上，网络不出 localhost，
> 所以"隐私"在 V0 几乎不是一个问题。
> **一旦 V1 部署到公网，这个论证立刻失效**，必须重新做完整的边界设计
> （见 [TechDesign 12 §7.3](../TechDesign/12-Web优先方案（平台迁移决策）.md)）。
> **不要把 V0 的阶段性强当永久承诺。**
>
> 相应地，原文档"本地优先（明细只存端侧 IndexedDB）"的表述**在 V0 不成立**——
> 与"账户下的物资通过服务器同步"直接冲突，已作废。

### 1.2 用户控制权

| 能力 | V0 要求 | 版本 |
| ---- | ---- | ---- |
| **改密码** | 需验证旧密码；改后**吊销其他会话** | **V0** |
| **登出** | 立即吊销当前会话 token | **V0** |
| **删除物品** | 软删除 + 5 秒撤销 | **V0** |
| **导出数据** | `sqlite3 keepfresh.db .dump` 即为完整导出（自用足够） | **V0**（原始形式） |
| 一键导出 JSON/CSV | 产品化的导出功能 | V1 |
| **彻底删除账号** | 级联删除该 `user_id` 的全部数据（外键 `ON DELETE CASCADE`） | V1（V0 手动删库即可） |
| 云备份开关 | — | V1 |
| 未成年人 | V0 不做年龄门槛，但**不收集**任何身份信息（只有用户名 + 密码哈希） | — |

### 1.3 合规

| 项 | V0 | V1 |
| ---- | ---- | ---- |
| 适用法规 | V0 是**本机自用软件**，不涉及对外提供服务 | 《个人信息保护法》最小必要原则；**ICP 备案**（见 11 R13） |
| 隐私说明 | **不需要**（数据不出本机） | 必须有隐私说明页，如实声明收集项（含"提醒计划会上传至服务端""语音会发送至 ASR 服务商"） |
| 免责声明 | **需要**：设置页"关于"常驻估算免责文案 | 同上，且更醒目 |
| 收款合规 | 不涉及 | V2 |

> 📌 **V0 的一个红利**：不需要备案、不需要隐私政策页、不需要任何资质。
> 这正是"先做本机自用"的核心价值——**把合规这个不确定性推迟到你有真实用户之后**。

## 2. 性能要求

| 场景 | V0 指标 | 说明 |
| ---- | ---- | ---- |
| 冷启动（Web 首屏可交互） | ≤ 1.5 秒（本机） | 本地服务端，无网络往返 |
| 列表渲染（500 条） | ≤ 1 秒 | 服务端分页 + `expire_at` 索引 |
| 列表接口响应（500 条） | ≤ 300ms | `EXPLAIN QUERY PLAN` 验证走索引 |
| 表单保存 → 列表出现新记录 | ≤ 1 秒 | 含服务端推算 |
| 知识库加载 | 服务端启动时一次性校验，**不阻塞前端** | — |
| 提醒计算 | **不适用**（V0 无提醒，无定时任务） | 状态是查询时推导的，不需要"算" |

> ⚠️ **原指标"提醒计算（定时任务扫描）单轮 ≤ 1 分钟"已删除**——V0 没有定时任务。

---

## 3. 可用性与离线

- **V0 明确不做离线能力**。服务端为唯一权威，**后端不可用时前端必须明确报错，并停止展示任何数据**——
  不允许显示陈旧缓存来"假装可用"（那会产生"我明明改了怎么没生效"的困惑，比报错更糟）。
- 前端在请求失败时给出**明确、生活化的提示**（"连不上本地服务，请确认后端已启动～"），
  而不是白屏或转圈。
- **弱网/无网场景在 V0 不适用**（数据不出本机）。
- **V1 起**：公网化之后再考虑离线与弱网（那时才有"地库/超市没信号"的真实场景）。

## 4. 兼容性

| 平台 | V0 要求 |
| ---- | ---- |
| **桌面浏览器** | **Chrome / Edge 最新版为首要目标**（Windows）；Firefox 兼容但不强求 |
| 屏幕 | **宽屏优先**（≥ 1280px 为主要设计宽度），窄到 1024px 不破版 |
| 移动端浏览器 | **V0 不保证**（但不写死尺寸，组件按响应式写，避免 V1 重写） |
| PWA / 添加到主屏幕 | ❌ V1 |
| 原生 App | ❌ V2 |

> ⚠️ 原表写"主流浏览器（Chrome/Edge/Safari）+ iPhone Safari 添加到主屏幕 + iOS Web Push 需 16.4+"，
> **这属于 V1 的目标**；V0 只需要在 Windows 桌面浏览器上跑通。

**开发环境要求**：Node 20+（本机 v24）、pnpm、git。**不需要任何第三方账号或开发者工具。**

## 5. 可维护性与配置化（一人公司的生命线）

| 项 | V0 要求 |
| ---- | ---- |
| 品类知识库 | `config/shelf_rules.json`，带版本号；**服务端启动时校验**，坏规则宁可起不来 |
| 文案库 | `config/copywriting.json`，同上 |
| **配置校验** | `pnpm validate:config`：schema + 禁止词 + 版本号递增检查 |
| 功能开关 | V0 **不需要**（单人单端，改代码比配开关快） |
| 错误日志 | 结构化 JSON 行日志：方法/路径/状态码/耗时/`userId`；**不含用户内容** |
| 数据库迁移 | `migrations/*.sql` + `schema_version` 表，顺序执行、只增不改 |
| 备份 | **拷贝 `data/keepfresh.db`**（SQLite 单文件）；建议每周一次 |
| 后端形态 | 本地 Node 进程，`pnpm dev` 启动；**无服务器运维负担**（因为还没有服务器） |

## 6. 安全（V0 的头号问题）

### 6.1 越权访问是 V0 最可能出的严重 bug

> 原文档这一节写的是"**不做用户密码体系（V1 依赖微信身份）**"——
> 微信身份随小程序放弃已不存在，而 V0 有真实账户，**这句话已作废并替换为下面的要求**。

**铁律**：所有对物资的读写**必须校验资源归属**：

```sql
-- ❌ 禁止：只按 id 查
SELECT * FROM items WHERE id = ?;

-- ✅ 必须：带 user_id 归属校验
SELECT * FROM items WHERE id = ? AND user_id = ?;
```

- `user_id` **只允许来自会话**，**绝不接受客户端传入**；
- 所有物资查询只走 `apps/server/src/services/`，且**函数签名第一个参数恒为 `userId`**；
- **必须有自动化测试**：用 A 的 token 对 B 的物资执行列表/详情/修改/删除四个动作，全部返回 **403/404**。

### 6.2 密码与会话

| 项 | 要求 |
| ---- | ---- |
| 密码哈希 | **argon2id**（推荐）或 bcrypt cost ≥ 12；**禁止明文 / MD5 / SHA1 / 无盐 SHA256** |
| 用户名 | 唯一索引（`username_lower`，大小写不敏感）；长度 3~32 |
| 密码长度 | ≥ 8 位 |
| 登录限流 | 连续失败 5 次 → 锁定 15 分钟（返回 **429**） |
| 会话 token | 32 字节 CSPRNG；**数据库只存 token 的哈希** |
| 会话有效期 | 30 天，滑动续期；登出即删除 |
| Cookie（若用） | `httpOnly` + `sameSite=Lax`（公网化后加 `secure`） |

### 6.3 其他

- **SQL 注入**：全部参数化绑定（`better-sqlite3` 的 `?`），**禁止字符串拼接 SQL**；
- **输入校验**：每个写接口用 **Zod** 校验，字段白名单（**禁止把请求体整体展开写库**）；
- **CORS**：V0 前后端同源（Vite proxy），**不需要开 CORS**；若开，白名单精确到 `http://localhost:5173`，**禁止 `*`**；
- **错误处理**：对外只返回 `{ code, message }`，**不泄露堆栈**；堆栈只进服务端日志；
- **日志**：**禁止打印密码、token、备注全文**；
- **仓库卫生**：`.gitignore` 必须包含 `*.db` / `.env` / `node_modules` / `dist` / `data/`（**已就位 ✓**）；
- **零第三方 SDK**：V0 不引入任何会外发数据的 SDK。

## 7. 无障碍（V1 起完整达成，V0 做到基础项）

- 字号适配浏览器缩放（不写死 `px` 布局宽度）；
- 表单控件有 `<label>` 关联，键盘可达；
- 颜色对比度满足 WCAG AA（**项目本就以"暖色 + 不刺眼"为基调，天然接近**）；
- 状态标签**不依赖单一红色**表达（色盲友好）——过期用"温和橙色 + 文字"，不用红色感叹号；
- 免责与"估算"标注必须有文字，不能只靠图标暗示。

## 8. 国际化（远期，不做）

- V0/V1 仅简体中文；知识库与文案结构预留 i18n 键位，避免后期重构。

## 9. V0 验收清单（对照本章）

- [ ] 用 A 的 token 对 B 的物资执行**列表/详情/修改/删除**，全部 **403/404**（自动化测试）；
- [ ] 数据库中 `password_hash` 为 argon2id/bcrypt 格式，**无明文**；
- [ ] `sessions` 表中**没有明文 token**（只有哈希）；
- [ ] 连续 6 次错误密码 → 第 6 次返回 **429**；
- [ ] 停掉后端 → 前端**明确报错**，且**不显示任何陈旧数据**；
- [ ] 500 条数据下列表 ≤ 1 秒、列表接口 ≤ 300ms；
- [ ] `git status` 中**没有** `*.db` / `.env` / `data/`；
- [ ] 日志抽样检查：**不含**密码、token、备注全文；
- [ ] 表单控件键盘可达、状态标签有文字（不只靠颜色）；
- [ ] 设置页"关于"里有免责声明常驻。
