# 保鲜盒 KeepFresh

> 跑在**你自己电脑上**的个人物资保质期管家：注册账号 → 手动录入买回来的东西 → 自动推算"真实可用期限" → 分组/筛选/搜索管理 → 标记用完或丢弃。
> 后端与前端同仓，`pnpm dev` 一条命令一起起。**它是未来移动端的"客户辅助端"——在电脑上总管物资。**

> ⚠️ **版本号约定（2026-08 收敛）**：全项目只用 **V0 / V1 / V2** 三个版本号，
> 与 P0 / P1 / P2 一一映射。**原 V0.5 / V1.0 / V1.1 / V1.2 / V2.0 / P1.1 一律废弃。**
> 范围唯一权威：[PRD/08-MVP范围与版本规划.md](./PRD/08-MVP范围与版本规划.md)。

## 为什么做这个

- **记不住**：冰箱深处的酸奶过期一周才发现，贵价护肤品开封后放到过期
- **算不准**：开封前后、夏冬气候不同，"保质期" ≠ "能吃的期限"
- **提醒太粗暴**：要么没有提醒，要么到期才弹一个冷冰冰的"已过期"

一句话：帮你把买的东西**用完**，而不是堆到过期。

## 当前版本（V0 · 物资总管 / PC 辅助端）

> PRD 依据：[PRD 08 §2](./PRD/08-MVP范围与版本规划.md)。
> **形态**：Vite + React + TS 前端（**仅 PC 桌面浏览器**）+ 本地 Node(Hono) + SQLite 后端，
> 同仓 `pnpm dev` 一条命令一起起。**不部署、不买服务器、不需要域名与备案。**

### V0 做（P0 必做）

| 模块 | 内容 |
| ---- | ---- |
| **账户** | 注册 / 登录 / 登出；用户名 + 密码（argon2id）；会话 token；**数据按账户隔离** |
| **记录** | 手动表单：品类（搜索/热门）→ 数量 → 购买日 → 开封状态 → 存储位置 → 备注 |
| **推算** | 品类基线 × 开封状态 × 气候档（手动档）三层引擎；展示依据文案与置信度 |
| **管理** | 完整列表：分组（冷藏/冷冻/储物柜/药箱/化妆台/其他）+ 排序 + 筛选 + 搜索 |
| **详情** | 全字段 + 推算依据 + 手动修改（校准样本记录） |
| **处置** | 已用完 / 已丢弃 / 转赠；**5 秒内可撤销** |
| **统计** | 极简三项：在库件数 / 本月处置件数 / 避免浪费件数（**不做图表**） |
| **知识库** | 50 类 `shelf_rules.json` + `copywriting.json`，服务端持有，启动时校验 |
| **设置** | 气候档位 / 默认存储位置 / 修改密码 |
| **工程** | monorepo + typecheck + vitest（`core/` 覆盖率 ≥ 80%）+ 一条命令启动 |

### V0 明确不做

> ⚠️ 这不是"以后再说"，而是**明确排除在 V0 之外**（设计文档保留，标注「V1 起实现」）。

- ❌ **一切提醒**（临期 / 过期 / 开封计时 / 检查）与页内横幅
- ❌ **一切推送通道**（Web Push / Bark / ntfy / 飞书机器人）
- ❌ **语音录入与 ASR**
- ❌ **PWA / 移动端适配 / 添加到主屏幕**
- ❌ **公网部署 / 域名 / 备案 / HTTPS 证书**
- ❌ **定时任务 / Cron / 常开服务端**
- ❌ **天气 API 自动气候**
- ❌ **拍照记录 / OCR**
- ❌ **家庭共享 / 多设备同步冲突**
- ❌ **金额统计**

> 🎯 **V0 不做提醒，所以它的目标是验证"数据记得住、推算算得准"，不是留存。**
> V0 的验证目标是"数据与推算是否可信"；留存与提醒效果属于 V1，
> **不要在 V0 阶段用留存量判断成败**——V0 没有提醒，留存必然不好看（PRD 08 §2.5 / §3）。

## 功能特性

- 🧮 **保质期推算**：品类基线 × 开封状态 × 气候因子，三层规则引擎，**可解释、可校准**（每件物品都能看到"为什么算这个日期"）
- 🍓 **生鲜果蔬支持**：状态驱动模型，给"建议窗口"，不承诺做不到的精确
- 🗂️ **完整管理视图**：按存储位置分组、按到期日/购买日排序、临期/过期/已开封筛选、关键字搜索——东西多了也找得到
- ✅ **处置闭环**：用完、丢弃、转赠，5 秒内可撤销；看得到"本月避免浪费 X 件"
- 💬 **生活化文案**：不吓人、不说教，建立"该处理了"的直觉
- 📖 **免责声明内置**：明确标注"估算"，不冒充食品安全检测
- 👤 **账户与数据隔离**：服务端 SQLite 为唯一权威，数据只有一份，换浏览器/重装前端都不丢
- 🔧 **规则即可配置**：品类规则是 JSON，改一条规则不用改代码

> 语音录入、拍照归档、端侧存储与四类温柔提醒等能力**不在 V0**（V0 的数据由服务端 SQLite 持有），见上文"V0 明确不做"。

## 路线图

> PRD 依据：[PRD 08 §3](./PRD/08-MVP范围与版本规划.md)。**只有 V0 / V1 / V2 三档。**

| 版本 | 名称 | 核心业务问题 | 关键交付 | 退出标准 |
| ---- | ---- | ---- | ---- | ---- |
| **V0**（P0，当前） | 物资总管（PC 辅助端） | **东西记得住吗？算得准吗？** | 账户 + 本地后端 + PC 网页 + 三层推算引擎 + 完整管理视图 | [PRD 08 §2.5](./PRD/08-MVP范围与版本规划.md) 的 7 条全绿；自己真实使用 ≥ 2 周，库存在 30 件以上 |
| **V1**（P1） | 提醒闭环（公网 + 移动端） | **提醒有没有用？** | 公网部署（含备案决策）+ 移动端可用 + 语音录入 + 四类提醒 + 推送通道 | 提醒点击率 ≥ 40%；48h 处置率 ≥ 50%；30 日留存 ≥ 20% |
| **V2**（P2） | 产品化 | **别人愿意付费吗？** | 家庭共享 + 深度统计 + 付费 + 主体资质 | 家庭空间周活 ≥ 30%；付费转化 ≥ 3% |

> **版本之间的硬门禁**：V0 的 PRD 08 §2.5 未全绿，**不进入 V1 开发**。
> 注意——"没达标"指的是**功能没做完或推算不准**，不是留存量不好看。

## 技术栈

- **前端**：Vite + React + TypeScript，**仅 PC 桌面浏览器**（Chrome / Edge）；仍按响应式写，避免 V1 重写
- **后端**：Node 20+ + **Hono** + **SQLite**（`better-sqlite3`），**本地运行**，与前端同仓
- **数据权威**：**服务端 SQLite 是唯一权威**——账户下的物资通过服务端同步，前端不做本地权威副本
- **逻辑层**：`packages/core` **纯 TS**（推算引擎 / 规则加载 / 类型与 Zod schema），**前后端共用**，未来移动端直接复用
- **鉴权**：用户名 + 密码（argon2id），会话 token，数据按账户隔离
- **API**：`/api/v1/*` REST + `Authorization: Bearer <token>`，**契约冻结**，V1 移动端无需改协议
- **规则引擎**：JSON 知识库（`config/shelf_rules.json` / `copywriting.json`，Git 管理），改规则不发版
- **AI 定位**：LLM 仅用于开发期辅助（起草代码、起草知识库初稿，**人工逐条审核**），**从不参与运行时生成期限数值**，保证推算可解释、可追责

## 快速开始

```bash
pnpm install    # 安装依赖（workspace 全量）
pnpm dev        # 并行启动：后端 :3000 + 前端 :5173（Vite proxy 把 /api 转发到 :3000）
pnpm test       # vitest：packages/core + 服务端纯逻辑
```

打开 <http://localhost:5173> 即可使用。

> **无需任何第三方账号、无需域名、无需部署**——不需要购买服务器、不需要备案、不需要注册任何云服务或推送服务。
> 环境只需 **Node 20+**（本机已具备 v24）与 **pnpm**；开发工具只需 VS Code + Git。
> 工程化细节见 [TechDesign/08-工程化与CI.md](./TechDesign/08-工程化与CI.md)，后端与 API 契约见 [TechDesign/03-服务端技术栈.md](./TechDesign/03-服务端技术栈.md)。
