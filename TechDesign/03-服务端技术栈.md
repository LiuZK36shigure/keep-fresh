# 03 · 服务端技术栈与 API 契约（V0：本地 Node + SQLite）

> 📌 **本章已按 2026-08 范围收缩整体重写**。原版本是"微信云开发 Serverless"（云函数 / 云数据库 /
> 定时触发器 / openid 身份），随"放弃小程序"**已完全作废**。
>
> **本章的 V0 定位**：定义 **V0 的后端形态、REST API 契约、鉴权与数据归属规则**。
> 这里的 API 契约是 V0 最重要的产出之一——**V1 的移动端将直接复用同一套接口**（PRD 08 §2.4）。
>
> **V0 不做**：公网部署、域名、备案、定时任务、推送发送、ASR 代理。
> 这些属于 V1，见 [12-Web优先方案](./12-Web优先方案（平台迁移决策）.md) §3~§6。
>
> PRD 依据：[08 §2 范围](../PRD/08-MVP范围与版本规划.md)、[07 非功能需求](../PRD/07-非功能需求.md)。

## 1. 选型：为什么是"本地 Node + SQLite"

| 维度 | **本地 Node + Hono + SQLite（选定）** | 云 Serverless（Workers + D1） | 自建 VPS |
| ---- | ---- | ---- | ---- |
| 部署成本 | **0**，`pnpm dev` 一条命令 | 需域名/账号/部署流程 | 需买机器、配证书 |
| 备案 | **不需要** | 公网发布需另行决策（PRD 11 R13） | 需要 |
| 数据可见性 | `sqlite3 keepfresh.db` 直接看，**调试极快** | 要过控制台/CLI | 要连远程 |
| 迁移成本 | schema 与 SQL 可平移到 Postgres/D1 | 无需迁移 | 无需迁移 |
| 离线可用 | **天然（就在本机）** | 需付费/代理 | 天然 |
| 代价 | 换机器要拷数据文件；只能自己用 | — | 月费 |

> **V0 决策**：本地 Node + SQLite。
> **理由不是"省钱"，而是"把不确定的环节全部推迟"**——V0 要验证的是**数据与推算是否可信**（PRD 08 §2.5），
> 任何与这个目标无关的工程复杂度都应该被排除。

### 1.1 技术栈明细

| 层 | 选型 | 理由 |
| ---- | ---- | ---- |
| 运行时 | **Node 20+**（本机已具备 v24） | — |
| HTTP 框架 | **Hono** | 极轻、TS 一流、Web 标准 API（`Request`/`Response`），**未来可几乎原样搬到 Workers** |
| 数据库 | **SQLite**（`better-sqlite3`） | 单文件、同步 API（写起来最短）、事务可靠；V0 单用户量级绰绰有余 |
| 迁移 | 自写 `migrations/` + `schema_version` 表 | 不引入 ORM 迁移框架，**顺序 SQL 文件 + 一个执行器**即可 |
| 校验 | **Zod** | 请求体校验与 `shared/types` 同源，**禁止手写校验分支** |
| 密码 | **argon2id**（`argon2` 包）或 bcrypt | 见 §4 安全 |
| 会话 | 不透明随机 token（32 字节），存 `sessions` 表 + httpOnly Cookie | 简单、可吊销；不用 JWT（V0 不需要无状态） |
| 测试 | **vitest** | 与前端、`core/` 同一套 |
| 进程管理 | `tsx watch` | 开发期零配置热重载 |

> **不用 ORM 的理由**：V0 的表只有 6 张，SQL 直写比配 Prisma/Drizzle 更快读懂，
> 也更容易在 V1 迁移时逐条复核。**若 V1 表数超过 12 张，再考虑引入 ORM。**

## 2. 目录与启动

```
keepfresh/
├─ packages/core/          # 纯 TS：engine（推算）/ rules（知识库）/ types  ← 前后端共用，未来 RN 复用
├─ apps/web/               # Vite + React + TS（PC 桌面浏览器）
├─ apps/server/            # Hono + SQLite
│   ├─ src/
│   │   ├─ routes/         # auth.ts / items.ts / categories.ts / settings.ts / stats.ts
│   │   ├─ middleware/     # auth.ts（会话校验）/ error.ts / validate.ts
│   │   ├─ db/             # index.ts（连接）/ migrations/*.sql / migrations.ts（执行器）
│   │   ├─ services/       # auth / items / stats（业务逻辑，可单测）
│   │   └─ index.ts
│   └─ data/keepfresh.db   # ← 数据文件（.gitignore）
├─ config/                 # shelf_rules.json / copywriting.json（知识库源文件，Git 管理）
├─ package.json            # workspace 根
└─ pnpm-workspace.yaml
```

```bash
pnpm install
pnpm dev        # 并行启动：server :3000 + web :5173（Vite proxy 把 /api 转发到 :3000）
pnpm test       # vitest（core/ + server/services）
pnpm typecheck
```

> **一条命令起前后端**是 V0 的硬验收项（PRD 08 §2.5 #1）。
> 用 `concurrently` 或 `pnpm --parallel -r dev`，**不要要求开发者开两个终端**。

## 3. REST API 契约（V0 · 未来移动端直接复用）

> **这是 V0 最需要写清楚的部分。** 以下契约是"保留接口"的具体形态——
> V1 做移动端时，**客户端只需要换 UI，不需要改协议**。

### 3.1 通用约定

| 项 | 约定 |
| ---- | ---- |
| 前缀 | `/api/v1`（**版本前缀必须有**，V1 增补能力时不破坏 V0 客户端） |
| 认证 | `Authorization: Bearer <token>`；浏览器端也可用 httpOnly Cookie（二选一，服务端都支持） |
| 请求/响应 | 一律 JSON；字段名 `camelCase` |
| 时间 | ISO 8601 字符串（`YYYY-MM-DD` 用于日期，UTC ISO 用于时间戳） |
| 成功响应 | 直接返回资源对象或 `{ items: [], total: n }` |
| 错误响应 | 统一 `{ error: { code, message } }`；**HTTP 状态码必须正确**（400/401/403/404/409/429/500） |
| 分页 | `?limit=&offset=`；列表默认 `limit=100`，上限 500 |
| 幂等 | 写操作由客户端生成 `id`（UUID v4），重复提交不产生重复记录 |

### 3.2 接口清单

#### 认证 `/api/v1/auth`

| 方法 | 路径 | 说明 | 请求 | 响应 |
| ---- | ---- | ---- | ---- | ---- |
| POST | `/register` | 注册 | `{ username, password }` | `201 { user, token }` |
| POST | `/login` | 登录 | `{ username, password }` | `200 { user, token }` |
| POST | `/logout` | 登出（吊销当前会话） | — | `204` |
| GET | `/me` | 当前用户 | — | `200 { user }` |
| PATCH | `/password` | 修改密码（需旧密码） | `{ oldPassword, newPassword }` | `204` |

#### 物资 `/api/v1/items`

| 方法 | 路径 | 说明 |
| ---- | ---- | ---- |
| GET | `/` | 列表。支持 `?status=&storage=&q=&sort=&order=&limit=&offset=` |
| POST | `/` | 新增（**服务端计算并落库推算结果**） |
| GET | `/:id` | 详情 |
| PATCH | `/:id` | 编辑（改品类/数量/日期/开封/存储/备注 → **服务端重算推算结果**） |
| DELETE | `/:id` | 删除（软删除，便于 5 秒撤销与统计） |
| POST | `/:id/dispose` | 处置 `{ type: 'used'\|'discarded'\|'gifted' }` |
| POST | `/:id/restore` | 撤销处置 / 撤销删除 |
| PATCH | `/:id/estimate` | 手动修正到期日 `{ newExpireAt, reason }`（写校准样本） |

**列表查询参数（V0 的"管理视图"全靠它）**：

| 参数 | 取值 | 说明 |
| ---- | ---- | ---- |
| `status` | `recorded` \| `opened` \| `expiring` \| `expired` \| `disposed` \| `active`(=未处置) | 筛选；**状态由服务端按到期日推算，不由客户端判断** |
| `storage` | `fridge` \| `freezer` \| `room` \| `shade` \| `medicine` \| `cosmetic` \| `other` | 分组视图 |
| `q` | 关键字 | 匹配 `categoryName` 与 `note` |
| `sort` | `expireAt`(默认) \| `buyDate` \| `createdAt` | 排序字段 |
| `order` | `asc` \| `desc` | — |

#### 其他

| 方法 | 路径 | 说明 |
| ---- | ---- | ---- |
| GET | `/api/v1/categories` | 品类列表（供表单下拉/搜索） |
| GET | `/api/v1/items/stats` | 极简统计：`{ activeCount, disposedThisMonth, savedThisMonth }` |
| GET | `/api/v1/settings` | 读取设置（气候档 / 默认存储位置） |
| PATCH | `/api/v1/settings` | 更新设置（**改气候档后，服务端批量重算未处置物品**） |
| GET | `/api/v1/knowledge/rules` | 知识库当前版本 + 内容（`shelf_rules.json`） |
| GET | `/api/v1/knowledge/copywriting` | 文案库 |
| GET | `/api/v1/health` | 健康检查（便于脚本/未来部署探活） |

### 3.3 为 V1 预留的接口（V0 **不在路由中注册**，但契约先定）

> 这些路径在 V0 返回 `501 Not Implemented`，**契约冻结**——移动端接入时不改协议。

| 方法 | 路径 | V1 用途 |
| ---- | ---- | ---- |
| POST | `/api/v1/items/batch` | 离线队列批量补传（移动端弱网必需） |
| POST | `/api/v1/items/voice` | 语音录入：`{ audio }` → `{ parsed, confidence }` |
| GET | `/api/v1/reminders/due` | 移动端拉取待提醒（替代服务端主动推的兜底） |
| POST | `/api/v1/push/subscribe` | 注册推送订阅（Web Push / 移动端 token） |
| DELETE | `/api/v1/push/subscribe` | 注销订阅（处理 404/410 失效） |
| GET | `/api/v1/sync/changes?since=` | 增量同步（多设备） |

### 3.4 契约冻结纪律

- **V0 已发布的字段不得删除或改语义**，只能新增可选字段；
- 破坏性变更必须走 `/api/v2`；
- 契约以 **Zod schema 为唯一真源**，放在 `packages/core/schemas/`，**前后端共用同一份**，
  这样"前端以为的字段"和"后端返回的字段"不可能漂移。

## 4. 鉴权、数据归属与安全（V0 的头号问题）

> 原文档在这个位置写的是"免鉴权：云函数内直接拿 openid"——**那条路已经不存在了**。
> 自建鉴权后，**越权是本项目 V0 最可能出的严重 bug**，必须逐条落实。

### 4.1 数据归属铁律

```sql
-- ❌ 绝对禁止：只按 id 查询/更新
SELECT * FROM items WHERE id = ?;
UPDATE items SET qty = ? WHERE id = ?;

-- ✅ 必须：所有读写都带 user_id 归属校验
SELECT * FROM items WHERE id = ? AND user_id = ?;
UPDATE items SET qty = ? WHERE id = ? AND user_id = ?;
```

- **实现方式**：所有 `items` / `settings` / `sessions` 相关查询**只走 `services/` 层**，
  且 `services/` 的函数签名**第一个参数恒为 `userId`**——让"忘记传 userId"在类型层面就报错；
- **验收**：用 A 的 token 请求 B 的 `itemId`，必须 **403/404**（不是 500，也不能返回数据）；
  这条用例**必须写进自动化测试**，不能只靠人工点。

### 4.2 密码与会话

| 项 | 要求 |
| ---- | ---- |
| 哈希 | **argon2id**（推荐）或 bcrypt cost ≥ 12；**禁止明文、MD5、SHA1、无盐 SHA256** |
| 用户名 | 唯一索引；长度 3~32；允许字母数字下划线；**大小写不敏感存储**（存 `username_lower`） |
| 密码强度 | 长度 ≥ 8；不做复杂度强制（V0 自用），但登录要限流 |
| 登录限流 | 同一用户名/IP 连续失败 5 次 → 锁定 15 分钟（`login_attempts` 表或内存计数） |
| 会话 token | 32 字节 CSPRNG 随机；**只存哈希**到 `sessions`（防数据库泄露即被盗用） |
| 会话有效期 | 30 天；每次请求可滑动续期；登出即删除 |
| Cookie（若用） | `httpOnly` + `sameSite=Lax` + 生产环境 `secure` |

### 4.3 其他 V0 安全要点

- **CORS**：V0 前后端同源（Vite proxy），**不需要开 CORS**；若开，白名单精确到 `http://localhost:5173`，**禁止 `*`**；
- **SQL 注入**：全部使用参数化绑定（`better-sqlite3` 的 `?` 占位），**禁止字符串拼接 SQL**；
- **输入校验**：每个写接口用 Zod 校验，白名单字段（**禁止把请求体整体展开写库**）；
- **错误处理**：对外只返回 `{ code, message }`，**不泄露堆栈**；堆栈只进服务端日志；
- **日志**：**禁止打印密码、token、完整会话信息**；
- **仓库卫生**：`.gitignore` 必须包含 `*.db`、`.env`、`node_modules`、`dist`——**数据文件与密钥绝不入库**；
- **备份**：V0 的备份就是**拷贝 `data/keepfresh.db`**；建议每周拷一次（这一点写进 09 章周节奏）。

## 5. 与 `packages/core` 的分工（避免逻辑漂移）

> 原文档的"端云逻辑漂移"风险（TechDesign 10 TR-5）在 V0 有了新的形态：
> 现在前后端**都**可能想算一遍到期日，如果各写一份，必然漂移。

| 逻辑 | 放在哪 | 理由 |
| ---- | ---- | ---- |
| **推算引擎**（三层规则、双模型、置信度） | `packages/core/engine` | **服务端唯一权威计算**；前端**只展示**，不重算 |
| 品类规则加载与校验 | `packages/core/rules` | 前后端共用同一份 `shelf_rules.json` |
| 领域类型与 Zod schema | `packages/core/schemas` | 契约唯一真源 |
| 状态推导（recorded/opened/expiring/expired） | `packages/core/engine` | **服务端算好写库/返回**，前端不做时间判断 |
| 列表排序/筛选/搜索 | 服务端 SQL | 数据量增长后前端过滤不可持续 |
| 提醒生成 | **V1 才做**（`core/reminder`） | V0 不实现，但字段保留 |

**约束**：`packages/core` **必须是纯计算**——不允许 `fetch`、不允许 `node:*`、不允许读文件。
存储与网络一律通过接口注入。这样：
① 前后端都能用；② 可以在纯 Node 下单测；③ **未来 React Native 直接复用**。

## 6. 知识库的加载与更新（V0）

- 源文件在 `config/shelf_rules.json` / `config/copywriting.json`（**Git 管理**，见 TechDesign 06）；
- 服务端启动时**读取 + Zod 校验**：`id` 唯一、`T0/T1` 非负、`aliases` 非空、文案禁止词扫描；
  校验失败**直接启动失败并打印错误**（宁可起不来，也不要带着坏规则跑）；
- 版本号写入 `knowledge_versions` 表（或 `settings` 单行），`GET /api/v1/knowledge/rules` 返回版本；
- **改规则流程**：改 JSON → `pnpm validate:config` → 重启服务端 → **前端刷新即生效**（不发版）；
- V1 改为静态托管分发时，机制不变，只是来源从本地文件换成 HTTP（**接口不用改**）。

## 7. V0 服务端验收清单

- [ ] `pnpm dev` 一条命令同时起前后端，**不需要开两个终端**；
- [ ] 注册 → 登录 → 登出 → 再用旧 token 请求，返回 **401**；
- [ ] **越权测试**：A 的 token 访问/修改/删除 B 的物资 → **403/404**（自动化测试覆盖，4 个动作都要测）；
- [ ] 数据库里 `password_hash` 是 argon2id/bcrypt 格式，**不存在明文**（抽查）；
- [ ] 连续 6 次错误密码 → 第 6 次返回 **429** 且提示锁定；
- [ ] 用非法 Zod 载荷（多余字段 / 类型错误 / 超长字符串）请求写接口 → **400**，且不写库；
- [ ] 删除一个物品 → 5 秒内 `POST /restore` 可恢复；超过 5 秒后前端不再展示撤销入口；
- [ ] 修改气候档 → 未处置物品的 `expireAt` **全部被重算**（抽查 3 条与 `core` 单测结果一致）；
- [ ] `pnpm typecheck` + `pnpm test` 全绿；`packages/core` 覆盖率 ≥ 80%；
- [ ] `git status` 中**没有** `*.db`、`.env`（`.gitignore` 生效）；
- [ ] 冷启动后 500 条物品的列表接口响应 **≤ 300ms**（`expireAt` 已建索引）。

## 8. V1 起才需要的东西（**明确不在 V0**）

> 列出这一节是为了让"以后要做什么"有明确落点，避免 V0 期间被这些事干扰。

| 能力 | V1 形态 | 备注 |
| ---- | ---- | ---- |
| 公网部署 | 域名 + HTTPS + 备案决策 | **PRD 11 R13**；这是 V1 的第一件前置事 |
| 常开服务端 | 必须常开，否则提醒失效 | Cloudflare Workers 免费版有 **CPU 10ms / 子请求 50** 的硬墙，**必须分片 cron**；KV 不适用，用 D1 |
| 推送发送 | Web Push（VAPID） | iOS 需 16.4+ 且已"添加到主屏幕"；权限拒绝后**无法程序化重申请** |
| 推送订阅生命周期 | 每次打开 upsert + 404/410 清理 | 订阅会**静默失效**，且 `pushsubscriptionchange` 在 iOS 不可靠 |
| ASR 代理 | 云 ASR（腾讯云/讯飞） | **必须在浏览器端归一化为 16k 单声道 WAV**，否则 Chrome 录音 100% 被拒 |
| 语音解析 | `core/parser` | 规则优先，接口 `VoiceInput` 已在 V0 留好 |
| 天气 API | 手动档 → 自动档 | "和风天气免费版"表述已过时，现在是每月前 5 万次 0 元 |

> 完整的技术风险与迁移路径见 [12-Web优先方案](./12-Web优先方案（平台迁移决策）.md)。
