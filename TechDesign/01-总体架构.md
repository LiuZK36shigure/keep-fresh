# 01 · 总体架构

> 本章回答：系统如何分层、**本地优先（Local-First）**如何落地、四条主数据流怎么走、
> 端（客户端）与云（服务端）的职责边界在哪里。
> PRD 依据：07 非功能需求（隐私/离线/性能）、09 §3.4 数据与后端、11 §9 隐私风险对策。

---

## 1. 架构原则（承接 PRD）

| 原则 | 含义 | 落地方式 |
| ---- | ---- | ---- |
| **本地优先** | 物品明细、照片、语音文本默认只存端侧 | 端侧存储为主；云端仅存"必要的最小数据"（见 §3） |
| **离线可用** | 无网时记录（语音降级手动）、查看、推算、横幅提醒照常 | 核心逻辑全部端侧运行；知识库本地缓存 | 
| **配置驱动** | 规则/文案/开关远程可更新，不发版 | 知识库 JSON + 版本号（见 06） |
| **端云分工明确** | 客户端是数据主体，云端是"配置分发 + 消息通道 + 匿名统计" | 见 §2 职责表 |
| **逻辑可测试** | 核心算法不依赖小程序运行时 | 纯 TS 模块 + vitest（见 08） |

## 2. 端云职责边界（最重要的一张表）

| 能力 | 端侧（小程序） | 云端（云开发） | 理由 |
| ---- | ---- | ---- | ---- |
| 物品记录（明细） | ✅ 唯一权威存储 | ❌ 不存（除非用户开云备份 P1 / 家庭共享 P1） | 07 §1 本地优先 |
| 照片 | ✅ 本地文件系统 | ❌ 默认不上传（可选备份 P1） | 07 §1.2 / F-04 隐私 |
| 推算引擎 | ✅ 端侧运行 | ❌ 不提供推算接口 | 离线可用 + 零延迟 + 隐私 |
| 知识库/文案 | ✅ 缓存 + 版本校验 | ✅ 托管最新版本（云存储） | 07 §5 远程更新 |
| 提醒计算（横幅） | ✅ 端侧生成今日提醒列表 | — | 离线兜底，打开必见 |
| 订阅消息推送 | ✅ 引导授权 + 上报提醒计划 | ✅ 定时触发器计算 + 调用发送 | 订阅消息只能云端发（05 §2） |
| 埋点 | ✅ 本地队列聚合 | ✅ analytics 云函数接收（匿名） | 03 §4 |
| 家庭共享（P1） | ✅ 视图层 | ✅ 家族数据 + 安全规则 | F-12 |
| 校准样本（P1） | ✅ 本地暂存 | ✅ 匿名上报（不含物品名） | 04 §5.3 |
| 支付订阅（V1.2） | ✅ 拉起微信支付 | ✅ pay 云函数 + 订单集合 | 10 §1.1 |

> **边界铁律**：凡是"用户内容"（物品名、数量、日期、照片）默认不出端；
> 凡是"产品配置"（规则、文案、开关）以云端为源、端侧缓存；
> 凡是"匿名统计"（事件、错误码、校准方向）允许上云，但必须可脱敏。

## 3. 云端只存什么（最小数据清单）

1. **remind_plans（提醒计划）**：仅当用户对某物品**授权了订阅消息**后，端侧才上报
   `itemId(端侧随机ID) + 品类名 + 到期日 + 文案键 + 提醒类型` —— 这是发送订阅消息的必要数据，
   必须在《用户隐私保护指引》中如实声明（09 §3）。未订阅的物品零上云。
2. **events（匿名埋点）**：无用户标识关联的事件流，定期清理。
3. **configs / knowledge_versions**：产品配置本身。
4. **users**：openid + 设置项（气候档案、提醒时间窗、推送开关）+ 订阅状态。
5. **families / memberships（P1）**：家庭共享关系；共享的物品明细只出现在家庭场景（成员确认后）。
6. **orders / subscriptions（V1.2）**：支付订单。

> 云端**不存**：未订阅物品的明细、照片内容、语音原文（识别后丢弃）、通讯录/位置轨迹（城市由用户自填）。

## 4. 模块划分（代码结构视角）

```
┌────────────────────────── 小程序（客户端） ──────────────────────────┐
│  pages/        页面：首页 / 语音页 / 确认页 / 我的物品 / 详情 / 设置    │
│  components/   自定义组件：语音大按钮 / 物品卡片 / 提醒横幅 / 确认卡片   │
│  store/        mobx store：items / settings / knowledge / analytics   │
│  services/     平台能力封装：storage / voice(WechatSI) / subscribe /  │
│                cloud(云函数调用) / weather(V1.2)                      │
│  core/         ★ 核心逻辑层（纯 TS，与小程序解耦，见 05）               │
│    parser/     语音解析器（规则版，F-01）                              │
│    engine/     推算引擎（三层规则 + 双模型，04）                        │
│    reminder/   提醒生成器（时机矩阵 + 合并 + 限频，05）                 │
│    knowledge/  知识库加载/版本校验/离线回退                             │
│    analytics/  埋点事件组装与队列                                      │
│    types/      领域类型（Item / CategoryRule / ...）                   │
│  assets/       图标、插画（本地化，压缩控制体积）                        │
└──────────────────────────────────────────────────────────────────────┘
┌────────────────────────── 云端（云开发） ─────────────────────────────┐
│  cloudfunctions/                                                      │
│    reminder/    每日定时：扫描 remind_plans → 生成待发消息 → 调 subscribe│
│    subscribe/   发送订阅消息（模板ID、频控、失败重试）                    │
│    knowledge/   知识库版本发布/查询（管理员调用）                        │
│    analytics/   接收匿名埋点（批量写入 events）                          │
│    family/      (P1) 家庭空间/成员/邀请码                                │
│    export/      (P1) 数据导出文件生成 / (P1) 账号删除                    │
│    pay/         (V1.2) 微信支付下单/回调/订阅状态                        │
│  database/      集合与安全规则（见 04）                                  │
│  storage/       shelf_rules.json / copywriting.json / 备份 / 导出       │
└──────────────────────────────────────────────────────────────────────┘
```

> 说明：`core/` 与 `cloudfunctions/` 之间的类型共享通过 `shared/` 包实现（monorepo，见 08）。

## 5. 四条主数据流

### 5.1 记录流（语音 → 保存 → 本地）

```
语音 → WechatSI 识别文本 → core/parser 解析（品类/数量/日期/开封）
   → 确认页（用户纠错，F-01/02）→ store 保存到本地存储
   → 端侧推算引擎立即算出到期日并展示（F-05）
   → 埋点 record_save
   → （黄金时机）引导订阅提醒：用户同意 → 上报 remind_plan 到云端
```

关键点：保存**不依赖网络**；订阅上报失败不影响保存（静默重试）。

### 5.2 提醒流（双通道）

```
通道A（订阅消息，云端定时）：
  定时触发器(每日 08:00 / 18:30) → reminder 云函数
    → 扫描 remind_plans 到期窗口 → 按合并/限频规则组装
    → subscribe 云函数发送（单发 ≤3 条/日 + 1 条汇总）
通道B（App 内横幅，端侧兜底）：
  小程序启动 / 回前台 → core/reminder 用本地物品计算"今日临期/过期清单"
    → 首页顶部横幅（GWT-19），离线也可见
```

### 5.3 配置流（知识库/文案更新）

```
启动/回前台 → 检查本地 knowledge 版本 → 云端最新版本号
   → 有新版本 → 拉取 shelf_rules.json / copywriting.json → 校验 → 落本地缓存
   → 失败/离线 → 用本地缓存（标注"离线版"），不阻塞任何功能
```

### 5.4 埋点流（本地聚合 → 批量上报）

```
core/analytics 事件入本地队列 →（达到阈值 20 条 或 30 秒）→ 批量调 analytics 云函数
   → 失败保留队列下次重试（不上传用户内容，见 07）
```

## 6. 性能预算（对照 07 §2）

| 场景 | 指标 | 架构对策 |
| ---- | ---- | ---- |
| 冷启动首屏可交互 | ≤ 2 秒（弱网 ≤ 3 秒） | 首页渲染不依赖网络；知识库后台异步拉取 |
| 语音 → 确认页 | ≤ 3 秒 | WechatSI 端侧识别 + parser 同步解析 |
| 物品列表渲染（500 条） | ≤ 1 秒 | 分页 + 节流渲染；本地索引按到期日排序 |
| 提醒计算（云函数） | 全部用户 ≤ 1 分钟 | remind_plans 按到期日建索引 + 分批扫描 + 幂等（见 03 §4） |
| 知识库更新 | 后台静默 | 版本号比较优先，全量 JSON ≤ 200KB，增量压缩（V1.1） |

## 7. 关键权衡记录（ADR 摘要）

| # | 权衡 | 结论 | 原因 | 若反转会发生什么 |
| ---- | ---- | ---- | ---- | ---- |
| ADR-01 | 推算引擎放端侧还是云端 | **端侧** | 离线可用（07 §3）+ 零延迟 + 隐私；云端只做"配置分发" | 断网无法记录/推算，违背 NFR；云端存物品明细违背隐私承诺 |
| ADR-02 | 提醒计划要不要上云 | **仅订阅授权的物品上云** | 订阅消息只能云端发送（05 §2）；不上云则订阅消息无法定时送达 | 全部明细上云 → 隐私事故面扩大（11 §9） |
| ADR-03 | 云端要不要做"推算接口"（服务端渲染） | **不做** | 端侧同构逻辑 + 远程 JSON 已覆盖；少一个接口少一份维护 | 端云规则漂移风险 → 用"同一份 shared 代码 + 同一份 JSON"从根上消除 |
| ADR-04 | 同步/备份 | **V1 不做，V1.1 按需** | 单设备验证期不需要；云备份默认关（07 §1.2） | 多设备用户流失 → 用数据说话（10 §4 H4） |

## 8. 本章验收（怎么算"架构落地了"）

- [ ] 断网状态下：记录一条物品（手动表单）→ 推算 → 首页横幅可见 → 全程无报错（GWT-04/19 的架构层保障）；
- [ ] 云端数据库里**不存在**任何未订阅物品的明细记录（可抽查）；
- [ ] `core/` 目录下所有模块可在纯 Node 环境跑通单元测试（不引用 `wx.*`）；
- [ ] 知识库 JSON 更新后，小程序**不重新发版**即使用新规则（07 §5 验收）。
