# 10 · 技术演进与风险

> 技术设计不是一锤子买卖：每个版本只解决一个业务问题（08 §3），技术增量随之分期投入。
> 本章给出 **V1 → V1.1 → V1.2 → V2** 的技术路线、每个阶段的验证目标、备选方案
> 与关键技术风险表。
> PRD 依据：08 MVP 与版本规划、09 §3 关键技术决策、11 风险与对策。

## 3. 各阶段关键技术设计要点

### 3.1 V1.1 家庭共享（F-12）——最大的架构增量

- 共享物品以**云端为权威**（多写者），与本地优先的"端侧为权威"相反——需显式设计冲突矩阵：
  - 同字段同时编辑 → 后保存者覆盖 + 合并备注（03 GWT-27，V1.1 简化版）；
  - 离线编辑 → 本地队列 + 联网冲突合并（乐观锁 `updatedAt` 比较）；
- 数据集合：`families`（空间）+ `memberships`（成员 + 角色）+ `family_items`（共享物品）；
- 权限：family 云函数校验成员关系；邀请码 24h 过期；成员可退出；
- 提醒分发：家庭成员各自订阅自己的提醒计划（remind_plans 按成员 openid 隔离）；
- **免费/付费墙**：家庭共享=付费卖点（10 §1.1）→ V1.1 先内测验证，付费门 V1.2 再关。

### 3.2 V1.2 自动气候（F-13 自动档）

- 天气 API：和风天气免费版（QPS 限额内），端侧定时（如每 6 小时）拉取城市天气；
- **降级链**：API 失败/超时/未授权定位 → 回退手动气候档（04 §4.3，绝不因 API 故障影响记录）；
- 城市来源：用户自填城市 → 可选地理定位（需授权，拒绝则维持手动）；
- 实现位置：`services/weather`（端侧）——气候档仍由端侧 engine 消费，云端不参与推算。

### 3.3 V1.2 OCR（F-14 试点）

- 微信 OCR 插件（`ocr-plugin`）识别包装日期文字 → 候选日期填入确认页（人工确认后生效）；
- 定位：**辅助录入**，不自动信任识别结果（食品安全红线 R1 不破）；
- 依赖：F-04 拍照记录已上线（照片本来就在端侧，OCR 也在端侧完成，不上传）。

### 3.4 V1.2 订阅支付（10 §1.1）

- pay 云函数：下单（`cloud.cloudPay.unifiedOrder`）→ 回调验签 → 更新 subscriptions 状态；
- 端侧：设置页"升级高级版" → 拉起支付 → 成功后解锁家庭共享/深度统计；
- 订阅状态缓存端侧 + 云端双份（防恢复丢失）；到期提醒 + 自动续费说明。

## 4. V2 候选：Flutter 原生 App（09 §3.1 决策）

**触发条件**：访谈证实"小程序订阅消息限制是用户流失主因"（08 §3 V2.0 退出标准）。

| 迁移项 | 复用/重写 | 说明 |
| ---- | ---- | ---- |
| core/（parser/engine/reminder） | ✅ 直接复用 | 纯 TS → Dart 翻译成本低；甚至可先用 Dart FFI 跑 JS？不——直接翻译，代码量不大 |
| 知识库/文案 JSON | ✅ 直接复用 | 与平台无关 |
| 数据模型（Item 等） | ✅ 翻译为 Dart 类 | 结构一一对应 |
| 提醒计划/云函数 | ✅ 基本复用 | 云函数不变，App 端换推送通道（APNs/FCM 或厂商通道） |
| UI 层 | ❌ 重写 | 这是换框架的必然成本（02 §1.1 已说明） |
| 语音识别 | ⚠️ 换系统 ASR | 端侧识别（iOS Speech / Android 系统） |
| 账号体系 | ⚠️ 需自建 | 微信登录保留 + 手机号/邮箱兜底（离开小程序生态的代价） |
| 端云调用 | ⚠️ 加 HTTP 接入层 | 小程序走 `wx.cloud.callFunction`；App/多端改走 REST：方案 A＝云函数 HTTP 触发 / 云开发 HTTP API 服务（不换平台）；方案 B＝迁腾讯云 Serverless + API 网关（10 §5 备选） |

**技术前置准备（现在就要做）**：`core/` 保持纯净（05 §4 纯 TS 约束）就是为这一天准备的；
知识库 schema 稳定（04 §3）避免未来双端解析两份 schema。

### 4.1 更远的多端：Web / 桌面 / 鸿蒙

> 核心逻辑是纯 TS（05 §4）+ 配置是 JSON（06）→ 这两个资产与平台无关，多端迁移 =
> "重写 UI + 替换平台能力（语音/推送/支付）+ 增加 HTTP 接入层"（见上表"端云调用"行）。

| 目标端 | 核心逻辑复用 | 主要工作 |
| ---- | ---- | ---- |
| Web（H5） | core/ 纯 TS 直接打包复用 | UI 重写；端云调用改 HTTP（云开发 HTTP API 服务或 @cloudbase/js-sdk）；语音换 Web 端方案 |
| 桌面（Windows/macOS/Linux） | core/ 纯 TS 直接复用（Electron/Tauri 或 Node 包装） | UI 重写；推送换系统通知；语音换系统 ASR |
| 鸿蒙（HarmonyOS） | core/ 与 ArkTS（TS 超集）兼容性高，翻译成本低 | UI 重写（ArkUI）；推送换华为推送；支付换华为支付 |

**现在就做、零成本的三件事**（迁移时才兑现收益）：

1. **云函数调用收口**：所有 `wx.cloud.callFunction` 只出现在 `services/cloud.ts` 一处，
   未来换 HTTP 客户端只改这一个文件（此约束写进 08 §4 CI 检查）；
2. **core/ 纯净约束不放水**（05 §4）：这是多端复用的根基；
3. **知识库/文案 schema 冻结**：稳定后不做破坏性变更，只做兼容性新增（04 §6 迁移纪律）。

## 5. 备选方案（触发条件明确，不提前行动）

| 备选 | 触发条件 | 方案 |
| ---- | ---- | ---- |
| 后端迁出云开发 | 云开发限额不够 / 需脱离微信生态 / 多端（App+H5） | 腾讯云 Serverless / 阿里云函数计算，数据库迁 MongoDB；云函数薄逻辑设计（03 §1）使迁移成本可控 |
| 引入跨端框架（Taro） | 出现"H5/抖音小程序多端"的强证据 | 重写 UI 层，core/ 与知识库不动 |
| 自建 ASR | WechatSI 免费额度不足且语音是核心路径 | 腾讯云 ASR（按量）或端侧系统识别 |
| 自建推送 | V2 转 App 后 | 厂商通道聚合（个推/极光）或自建 APNs/FCM |

## 6. 关键技术风险与对策

| # | 风险 | 概率/影响 | 对策 | 监控信号 |
| ---- | ---- | ---- | ---- | ---- |
| TR-1 | 订阅消息被用户拒绝/平台收紧，提醒形同虚设 | 高/高 | 横幅兜底已内置（GWT-19）；记录成功页黄金时机引导（05 §2）；V2 转 App 推送 | 订阅授权率、提醒关闭率（≤15%，05 §6） |
| TR-2 | 云开发免费额度不足 | 中/中 | 埋点聚合降频（07 §2）；remind_plans 及时清理；额度周报监控（03 §6） | 用量月报，提前 2 月预警 |
| TR-3 | 规则引擎准确性不足（推算修改率 > 20%） | 中/高 | 保守原则 + 置信度表达（04 §5）；校准反馈回路（05 §2.4）；知识库周更（06） | `estimate_modified` 占比（01 §3.2） |
| TR-4 | 主包超 2MB / 列表性能不达标 | 中/中 | 分包策略（02 §6）；分页渲染；真机性能自测清单 | 包体积检查、500 条列表帧率 |
| TR-5 | 端云逻辑漂移（core 与云函数规则不一致） | 低/中 | 同一份 shared 代码 + 同一份 JSON（01 ADR-03）；CI 校验（08 §4） | CI 红灯即阻断发版 |
| TR-6 | 语音插件额度/稳定性 | 中/中 | 降级手动表单（GWT-04）；同义词词典持续迭代（11 §6） | record_voice_fail 占比 |
| TR-7 | 单人中断期（考试/生病） | 高/高 | 全文档化（本套文档 + 代码注释）；配置化救火（06）；Git 全量备份（08 §6） | 无（习惯性纪律） |
