# 06 · 配置化与远程更新

> 一人公司的生命线（09 铁律 3："可配置 > 可开发"）：规则、文案、开关全部远程可更新，
> **改一个 JSON 能解决的事，绝不上线一个新版本**（07 §5、11 §8）。
> 本章定义配置资产清单、拉取链路、发布流程与版本管理。

---

## 1. 配置资产清单

| 配置 | 文件名 | 内容 | 更新频率 | 影响面 |
| ---- | ---- | ---- | ---- | ---- |
| 品类知识库 | `shelf_rules.json` | 品类基线 + 气候系数 + 词典（aliases/日期词/数量词） | 每周（审核后） | 推算、解析、文案 |
| 文案库 | `copywriting.json` | 生活化文案模板 | 按需 | 提醒、引导、反馈 |
| 功能开关 | `feature_flags.json` | 新功能灰度、紧急关闭（如提醒某类型暂停） | 随时 | 功能可用性 |
| 品类图标映射 | `category_icons.json` | 品类 → 图标/emoji | 按需 | 展示 |
| 紧急公告 | `announcement.json` | 顶部公告（如知识库更新日志、免责提醒） | 按需 | 展示 |

> 所有配置**必须带 `version` + `publishedAt`**，端侧按版本号增量拉取（04 §6）。

---

## 2. 拉取链路（端侧，06 §5.3 数据流）

```
小程序启动 / 回前台
  → knowledgeStore.checkUpdate()
    → 本地缓存版本 v_local 与 云端最新版本 v_remote 比较（knowledge 云函数，轻量）
    → v_local == v_remote → 结束（零流量）
    → 有新版 → 全量拉取 JSON（≤200KB）→ schema 校验 → 原子写缓存（新 key）
    → 失败/离线 → 继续用旧缓存（标注"离线版/上次更新：x 天前"），不阻塞任何功能
```

**细节要求**：

1. **校验先行**：JSON 必须通过 schema 校验（id 唯一、T0/T1 非负、aliases 非空、禁止词检查）才落缓存；
   校验失败视为"无更新"，并记录错误日志（防上游手滑毒死全量用户）；
2. **原子替换**：先写新 key（`kf_knowledge_v{ver}`）再删旧 key，崩溃不留半截文件；
3. **静默更新**：不打断任何用户操作；更新完成后若涉及"已展示推算依据"，历史 Item 不受影响
   （ruleVersion 字段保证可追溯）；
4. **通知面**：知识库更新日志在设置页展示（F-13 知识库版本项），用户可查"这次改了什么"。

---

## 3. 云端发布流程（一人公司版）

```
编辑源文件（仓库 config/ 目录，Git 管理，带变更说明）
  → 本地校验脚本：node scripts/validate.js config/shelf_rules.json
      · schema 校验 + 禁止词扫描（05 §4 惊吓词表）+ 版本号递增检查
  → 通过 → 上传云存储 configs/ + 写 knowledge_versions 台账（版本/变更说明/发布日期）
  → 灰度：先用 feature_flags 对新版知识库灰度 10% 用户（P1 简化：直接全量，回滚靠旧版备份）
  → 监控：24h 内观察"推算修改比例"与错误日志，异常立即回滚（云存储切回上一版本）
```

**回滚**：云存储保留最近 5 个版本（`shelf_rules_2025.07.01.json` 等），回滚 = 切换 knowledge 云函数返回的版本指针，秒级生效。

## 4. 功能开关（Feature Flag）设计

```jsonc
{
  "version": "2025.07.01",
  "flags": {
    "remind.check":     true,   // 检查提醒开关（紧急可关）
    "remind.opened":    true,   // 开封计时提醒
    "remind.channel.subscribe": true,  // 订阅消息渠道开关（紧急可关，2026-08）
    "remind.channel.service_account": false, // 服务号渠道开关（V1.2 启用，2026-08）
    "voice.provider":   "wechatsi", // 语音提供方：wechatsi | tencent_asr（B 方案切换，2026-08）
    "voice.parser.v2":  false,  // 解析器新词典灰度
    "stats.achievements": false, // P1 功能灰度
    "knowledge.gray":   false   // 知识库灰度发布开关
  }
}
```

- 端侧 `featureFlags` 缓存随知识库一起拉取（合并进 KnowledgeBundle）；
- 规则：**新功能默认关 → 灰度开 → 全量开**；出问题先关开关，再慢慢修（07 §5、11 §8）；
- 每个 flag 必须带注释用途与负责人（就是自己），防止三个月后看不懂。

## 5. 配置与代码的关系（边界约定）

| 内容 | 放配置（JSON） | 放代码（TS） |
| ---- | ---- | ---- |
| 品类基线、系数、词典 | ✅（04 §3） | ❌ |
| 文案模板 | ✅（04 §4） | ❌ |
| 提醒时机分档表（05 §1.2） | ✅（并入 shelf_rules 或独立 timing.json） | ❌ |
| 解析算法流程、引擎计算逻辑 | ❌ | ✅（core/parser、core/engine） |
| 数据模型结构 | ❌（版本迁移函数必须代码化） | ✅ |

> 判定标准（11 §11 复杂度上限）：**新增一条规则必须能写进一行 JSON，否则重新设计**。
> 逻辑与数据分离后，修改规则 = 发配置 = 0 代码、0 发版、5 分钟生效。

---

## 6. 验收清单

- [ ] 修改 shelf_rules.json 一个系数 → 云端发布 → 小程序冷启动后新系数生效（不需发版）；
- [ ] 断网启动小程序 → 使用缓存知识库正常记录/推算，界面标注"离线版"；
- [ ] 发布一个 schema 非法的 JSON → 端侧校验拒绝、不崩溃、日志有记录；
- [ ] 关闭 `remind.check` 开关 → 检查提醒立即停止（当天生效）。
