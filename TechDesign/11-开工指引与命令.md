## 1. 阶段①：monorepo 骨架（约 15 分钟）

> **思路沿用原文**（根 `package.json` + 一份 `tsconfig` + 一份 `vitest.config.ts` + 冒烟文件），
> **目录改为 V0 的真实结构**（pnpm workspace，见 [12 章附录](./12-Web优先方案（平台迁移决策）.md) 的推荐目录）：

```
keep-fresh/
├─ package.json            # 根：workspace scripts（pnpm dev / typecheck / test）
├─ pnpm-workspace.yaml
├─ tsconfig.base.json      # 共享编译选项
├─ .gitignore              # 见 §0 ③
├─ packages/
│  └─ core/                # ⭐ 纯 TS 领域层（engine / knowledge / types；parser、reminder 空占位）
│                          #    零 IO：禁 fetch / node:* / fs / 数据库 / localStorage
├─ apps/
│  ├─ web/                 # Vite + React + TS（仅 PC 桌面浏览器）
│  └─ server/              # Node + Hono + SQLite（better-sqlite3）
├─ config/
│  └─ shelf_rules.json     # 50 类知识库（阶段⑥）

└─ docs/tech-debt.md
```

### 1.1 根 package.json（V0 版）

```json
{
  "name": "keep-fresh",
  "private": true,
  "scripts": {
    "dev": "pnpm -r --parallel dev",
    "typecheck": "pnpm -r typecheck",
    "test": "vitest run",
    "test:watch": "vitest",
    "validate:config": "node config/scripts/validate.js"
  }
}
```

### 1.2 安装工具链

```powershell
pnpm add -D typescript vitest @types/node tsx
```

### 1.3 tsconfig.base.json（思路同原文，改为 base + 各包继承）

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "Bundler",
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "skipLibCheck": true,
    "esModuleInterop": true,
    "noEmit": true
  }
}
```

> ⚠️ **注意 `types`**：原文在根 `tsconfig.json` 里写了 `"types": ["node"]`。
> V0 的 `packages/core` **不应**包含 `"node"` 类型——**一旦有人写出 `process.` 或 `node:fs`，
> 有 node 类型就会编译通过**（[05 §4](./05-核心模块设计.md) 零 IO 约束靠这个兜底：
> `core` 的 tsconfig **不加载 node 类型**，误用即编译报错）。

### 1.4 vitest.config.ts（覆盖 core 与 server）

```ts
import { defineConfig } from 'vitest/config'

export default defineConfig({
  test: {
    include: ['packages/core/src/**/*.test.ts', 'apps/server/src/**/*.test.ts'],
    coverage: { include: ['packages/core/src/**'], thresholds: { lines: 80 } },
  },
})
```

### 1.5 冒烟文件（验证链路通）

`packages/core/src/types/index.ts` 写一个最小类型（完整 `Item` 模型等阶段②）：

```ts
/** 品类规则（完整 schema 见 TechDesign/04 §3，阶段⑥填充） */
export interface CategoryRule {
  id: string
  name: string
  model: 'date' | 'state'
}
```

`packages/core/src/smoke.test.ts`：

```ts
import { describe, expect, it } from 'vitest'
import type { CategoryRule } from './types'

describe('smoke', () => {
  it('类型与测试链路可用', () => {
    const rule: CategoryRule = { id: 'milk_fresh', name: '鲜牛奶', model: 'date' }
    expect(rule.model).toBe('date')
  })
})
```

## 2. 日常开发循环（以后每次改动都跑）

```powershell
pnpm dev               # 前端 :5173 + 后端 :3000 同时起（阶段②起可用）

pnpm validate:config   # 阶段⑥起：知识库/文案校验（schema + 禁止词 + 版本号）
```

```powershell
# core/ 内不得出现任何 IO（命中即失败，建议后续接进 CI）
Select-String -Path packages/core/src/**/*.ts -Pattern 'fetch\(|node:|from .fs.|better-sqlite3|localStorage|process\.env'
```

## 3. V0 的实际阶段（①~⑦，每阶段带"完成定义"）

> **替代原文"阶段②~⑤"表**。顺序按依赖排列：**先有账户与库，再有算法，再有接口，最后才有界面**。
> 阶段划分方法沿用原文原则：**每阶段可独立验收、可独立提交、半成品不留半截**（[10 §6 TR-V0-4](./10-技术演进与风险.md)）。

| 阶段 | 做什么 | 依据文档 | **完成定义** |
| ---- | ---- | ---- | ---- |
| **① 工程骨架** | monorepo + 根 scripts + tsconfig + vitest + 冒烟（见 §1） | 11 §1、[12 §5](./12-Web优先方案（平台迁移决策）.md) | `pnpm typecheck` 0 错误；`pnpm test` 1 个用例通过；`packages/core` 不加载 node 类型 |
| **② 后端骨架 + 账户** | `apps/server`：Hono 起服 + `/api/v1/*` 前缀 + SQLite 连接（WAL/busy_timeout）+ `users`/`sessions` 表 + 注册/登录/登出/改密路由 | [09 §2.5](./09-安全与隐私架构.md)、PRD 08 §2.2「账户」 | 注册→登录→带 token 访问受保护路由→登出后旧 token 401；**用户表里是 argon2id 哈希**；登录 5 次失败被退避；并发注册同名只有一条成功 |
| **③ 数据模型与迁移** | `items` / `settings` / `calibration_samples` 表 + `schema_version` 表 + 顺序迁移脚本 + 外键与索引 | 04 章（schema）、PRD 08 §2.4 | `pnpm dev` 首次启动自动建库到最新版本；**空库 → 最新版**与**旧版 → 最新版**两条路径都有测试；重复启动幂等；索引含 `(user_id, expire_at, status)` |
| **④ 推算引擎**（`core/engine`） | 三层规则（品类基线 × 开封状态 × 气候档）+ 日期/状态双模型 + `reasonText`/置信度 + 状态驱动窗口 + tips | [05 §2](./05-核心模块设计.md)、04 全章 | 04 §2 示例品类 × 各气候档用例全绿；`reasonText` 与 `expireAt` 逐位一致；`core/` **零 IO 静态检查通过**；`core/` 覆盖率 ≥ 80% |
| **⑤ REST API** | 物资 CRUD + 列表查询（分组/排序/筛选/搜索/分页）+ 处置与撤销 + 极简统计 + 设置 + 知识库读取；**每条 SQL 带 `WHERE id=? AND user_id=?`** | 03 章（新）、[09 §2.5 第 3 条](./09-安全与隐私架构.md) | **越权测试绿**：A 的 token 请求 B 的物资 → 403；A 猜 id 做 PUT/DELETE → 403/404；搜索传 `' OR 1=1 --` 无异常；500 条分页查询 ≤ 100ms |
| **⑥ 前端管理视图**（`apps/web`） | 登录/注册页 + 手动录入表单（品类搜索/热门）+ 列表（分组/排序/筛选/搜索）+ 详情（推算依据 + 手动修改）+ 处置与 5 秒撤销 + 极简统计 + 设置子集 | PRD 08 §2.2、02 章（基调） | 闭环可走通：登录 → 录入 → 看到推算依据 → 修改 → 标记用完 → 统计变化 → 5 秒内撤销；500 条下列表渲染 ≤ 1 秒；**刷新/换浏览器数据仍在**（服务端权威） |
| **⑦ 知识库种子 + 自用验证** | `config/shelf_rules.json`（50 类）+ `copywriting.json` + `validate.js`；然后**自己真实录入 ≥ 30 件、连续使用 ≥ 2 周** | 04 §3/§4、06、[PRD 08 §2.5](../PRD/08-MVP范围与版本规划.md) | `validate:config` 全绿；每类带依据来源（食品安全红线）；**PRD 08 §2.5 的 7 条全部通过**；库存在 30 件以上且保持更新 |

> 📌 **阶段 ①~⑥ 是"写代码"，⑦ 是"验代码"**——原文"阶段②~⑤"表没有"自用验证"这一步，
> 而 V0 的退出标准恰恰是**"自己真实使用 ≥ 2 周"**（PRD 08 §3），所以 V0 必须显式留出 ⑦。
>
> 📌 **不需要的阶段**（原文有、V0 没有）：小程序骨架与分包、云函数、语音解析器实现、
> 提醒生成器实现、推送通道接入、定时任务、公网部署。
