# 04 · 数据模型与存储

> 本章定义全部数据结构：端侧领域模型（Item）、云端集合（users / remind_plans / events…）、
> 知识库 JSON schema（shelf_rules.json / copywriting.json）、版本管理与数据迁移策略。
> PRD 依据：04 推算规则（字段结构）、05 提醒策略（提醒计划）、07 §1 隐私（本地优先）、07 §5 配置化。

## 1. 端侧核心模型：Item（物品）

> 存储于本地 `wx.setStorageSync('kf_items_v1')`。**字段以 JSON Schema 形式在 `shared/types` 定义**（08）。

```typescript
interface Item {
  // ── 标识 ──
  id: string;                 // 端侧随机 ID（uuid），不上云（除非订阅/共享）
  categoryId: string;         // 知识库品类 ID；自定义物品为 'custom:xxx'
  categoryName: string;       // 展示名（保存时快照，防止知识库改名后历史错乱）
  categoryModel: 'date' | 'state';  // 日期驱动 / 状态驱动（04 §7）

  // ── 记录要素（F-02 表单字段）──
  qty: number;                // 数量（默认 1；>1 仅统计与展示，04 §3.3）
  buyDate: string;            // 'YYYY-MM-DD'（确认页校验：不得晚于今天，04 §6）
  openedAt: string | null;    // 开封日期（null = 未开封）
  storageLocation: 'fridge' | 'freezer' | 'room' | 'shade' | 'medicine' | 'cosmetic' | 'other';
  note: string;               // 备注（可选）

  // ── 推算结果（保存时由引擎写入，F-05）──
  estimate: {
    expireAt: string;             // 推算到期日（状态驱动 = 窗口下限）
    windowEndAt: string;          // 状态驱动：窗口上限（日期驱动 = expireAt）
    confidence: 'high' | 'mid' | 'low';   // 置信度档（04 §5.1）
    reasonText: string;           // 依据文案（"基线 7 天 × 夏季系数 0.8 ≈ 6 天"）
    ruleVersion: string;          // 推算所用知识库版本（可追溯！）
    climateFactors: string[];     // 生效的气候档（如 ['high_temp', 'humid']）
    manual?: {                   // 用户手动修正（F-06 反馈回路）
      correctedAt: string;
      newExpireAt: string;
      reason: 'actual_bad' | 'still_fine' | 'other';
    };
  };

  // ── 状态机（06 §2）──
  status: 'recorded' | 'opened' | 'expiring' | 'expired' | 'disposed';
  postponedCount: number;       // 延后次数（上限 2，05 §5）
  disposedAt: string | null;
  disposeType: 'used' | 'discarded' | 'gifted' | null;  // F-08

  // ── 附件与审计 ──
  photos: string[];             // 本地文件路径（wx.env.USER_DATA_PATH/photos/…，F-04）
  createdAt: string;
  updatedAt: string;
  reminders: ReminderRecord[];  // 已触发的提醒记录（去重 + 展示"已提醒过"）
}

interface ReminderRecord {
  type: 'expiring' | 'expired' | 'opened' | 'check';
  triggerAt: string;            // 计划触发日
  sentVia: 'banner' | 'subscribe';  // 渠道
}
```

**状态机流转**（对应 06 §2）：`recorded → opened → expiring → expired → disposed`，
延后（postpone）不改状态只推迟提醒；`disposed` 后移入本地"已完成"归档（保留 90 天用于统计与撤销）。

## 2. 端侧辅助模型

```typescript
interface Settings {
  climate: {                    // 气候档案（F-13，04 §4.2）
    city?: string;              // 城市（自填，用于季节判断展示）
    summerMode: boolean;        // 夏季高温开关
    humidMode: boolean;         // 潮湿开关
    plumRainMode: boolean;      // 梅雨开关（V1 手动，V1.2 自动覆盖）
    autoClimate: boolean;       // V1.2：天气 API 自动（默认 false）
  };
  remind: {
    window: [8, 21];            // 提醒时间窗（默认 08:00-21:00）
    quietHours: [];             // 免打扰时段
    types: { expiring: true; expired: true; opened: true; check: true };
    dailyCap: 3;                // 单发上限（05 §3）
  };
  privacy: {
    cloudBackup: false;         // 云备份默认关（07 §1.2）
  };
}

interface KnowledgeBundle {     // 本地缓存的知识库
  version: string;              // 如 '2025.07.01'
  publishedAt: string;
  shelfRules: CategoryRule[];
  copywriting: CopyText[];
  featureFlags: Record<string, boolean>;
}
```

## 3. 知识库 Schema：shelf_rules.json（对应 04 §2/§4）

```jsonc
{
  "version": "2025.07.01",
  "publishedAt": "2025-07-01T00:00:00+08:00",
  "climateFactors": {                    // 04 §4.1 气候系数表（k）
    "temp_normal": 1.0, "temp_hot": 0.8, "temp_extreme": 0.7,
    "humid_dry": 1.0, "humid_wet": 0.8,
    "season_plum": 0.7,                  // 叠加
    "storage_mismatch": 0.5,             // 应冷藏未冷藏
    "minFactor": 0.5, "maxFactor": 0.5   // 叠加上限/保底（04 §4.1）
  },
  "categories": [
    {
      "id": "milk_fresh",
      "name": "鲜牛奶",
      "aliases": ["牛奶", "纯牛奶", "鲜奶"],        // 语音解析同义词（F-01）
      "category": "乳制品",
      "model": "date",                            // 'date' | 'state'
      "storageDefault": "fridge",                 // 默认存储位置
      "T0": { "fridge": 7 },                      // 未开封期限（按位置分档，天）
      "T1": { "fridge": 3 },                      // 开封后期限
      "climateSensitivity": "high",               // high|mid|low（04 §4.4）
      "unitPrice": 6.5,                           // 单价参考（避免浪费金额统计，F-11）
      "conservative": false,                      // 婴幼儿/药品强制保守（04 §5.2）
      "specialRules": { "summerFactor": 0.7 },    // 品类级特殊系数
      "tips": ["牛奶建议冷藏，室温下请尽快饮用"],   // 情境化科普（04 §7.4）
      "source": "包装通用规律 + 公开食品安全常识"    // 依据来源（04 §2，防拍脑袋）
    },
    {
      "id": "strawberry",
      "name": "草莓",
      "aliases": ["草莓", "士多啤梨"],
      "category": "水果",
      "model": "state",                           // 状态驱动（04 §7）
      "storageDefault": "fridge",
      "window": [1, 2],                           // 典型窗口（天）
      "checkRhythm": [2],                         // 检查提醒：第 2 天看一眼
      "climateSensitivity": "high",
      "unitPrice": 15.0,
      "tips": ["草莓勿水洗后存放"],
      "source": "..."
    }
  ]
}
```

> **自定义物品兜底**（04 §6）：`id: 'custom:xxx'`，用户在确认页填"期望期限"，
> 端侧以 `model: 'date'` + 用户期限保存，并记为模板学习样本（P2）。

## 4. 知识库 Schema：copywriting.json（05 §4）

```jsonc
{
  "version": "2025.07.01",
  "templates": [
    { "key": "expiring.food",      "text": "冰箱里的{name}还有{days}天到期，{action}～" },
    { "key": "expiring.fresh",     "text": "{name}是今天到期的选手，晚上做个{recipe}怎么样？" },
    { "key": "expired",            "text": "这盒{name}已经悄悄过期了，是时候说再见啦。" },
    { "key": "opened.timer",       "text": "{name}开封{days}小时了，请在{deadline}前用完哦。" },
    { "key": "summary",            "text": "今天冰箱有{n}样东西值得吃掉：{list}。" },
    { "key": "positive.monthly",   "text": "这个月你避免了{saved}元浪费，够请自己喝一杯奶茶啦！" },
    { "key": "empty.guide",        "text": "买完东西，对它说句话，剩下的交给我～" }
  ]
}
```

> 文案带 `{name}/{days}` 等占位符，端侧渲染时填充；键位结构同时是 i18n 预留（07 §8）。
> **禁止词**（05 §4）："库存告急""请立即处理"等惊吓式表达——写入 CI 校验规则（08 §5）。

## 5. 云端集合设计

### 5.1 users

```jsonc
{
  "_id": "auto",
  "_openid": "oXXXX",          // 云开发自动注入，仅作标识
  "settings": { /* 与端侧 Settings 相同结构（用于多端一致，P1 后） */ },
  "subStatus": { "subscribeMsg": true, "pay": "none|active|expired" },
  "createdAt": "2025-07-01T00:00:00+08:00",
  "lastActiveAt": "..."
}
```

### 5.2 remind_plans（订阅消息的"提醒任务"，01 §3 最小数据）

```jsonc
{
  "_openid": "oXXXX",
  "itemId": "端侧随机ID",        // 与端侧 Item.id 对应（脱敏：云端不存完整物品）
  "name": "鲜牛奶",              // 品类名（订阅消息模板需要）
  "expireAt": "2025-07-10",     // 到期日（服务端计算时点用）
  "remindType": "expiring",     // expiring|expired|opened|check
  "windowStart": "2025-07-07",  // 提醒窗口起点
  "copyKey": "expiring.food",   // 文案键（内容从 configs 取，不重复存储）
  "status": "active|sent|done|canceled",
  "sentDates": ["2025-07-07"],  // 已发送日期（幂等去重）
  "postponeLeft": 2,            // 延后剩余次数（05 §5）
  "createdAt": "..."
}
```

> 物品被处置/删除时，端侧调用云函数删除对应 remind_plan（`status: canceled`），
> 保证云端不残留过期任务（也符合"可彻底删除"承诺，07 §1.2）。

### 5.3 events（匿名埋点，07 §1 最小收集）

```jsonc
{
  "event": "record_save",          // 白名单事件名（03 §4 埋点表）
  "ts": 1751356800000,             // 时间戳
  "props": { "category": "乳制品", "isVoice": true },  // 白名单字段
  "anonId": "sha256(openid+salt)[0:16]"  // 不可逆匿名标识（不做画像，仅漏斗粗分）
}
```

### 5.4 其他集合（P1/V1.2 预留，schema 在对应版本设计）

`families` / `memberships`（P1 家庭共享）、`calibration`（P1 匿名校准样本）、
`orders` / `subscriptions`（V1.2 支付）、`knowledge_versions`（配置版本台账，06）。

## 6. 版本管理与数据迁移（R7 单人开发的生命线）

| 场景 | 策略 |
| ---- | ---- |
| Item 模型升级 | 本地 key 版本化（`kf_items_v1` → `kf_items_v2`）+ 迁移函数注册表：`migrations: [{from:1, to:2, fn}]`，启动时按序执行 |
| 知识库版本 | 端侧缓存 `KnowledgeBundle.version`；云端新版本 → 全量替换缓存（V1 全量 ≤200KB；V1.1 起做增量补丁） |
| 云端集合字段 | 云函数读取时做"字段默认值"兜底（`??` 模式），避免老数据炸新代码 |
| 破坏性变更 | 一律双版本并行过渡（新旧字段并存 1 个版本周期），禁止直接删字段 |
| 数据导出 | 导出 JSON 含 `schemaVersion`，保证未来可迁移（07 §1.2） |

## 7. 数据一致性原则（端侧为权威）

1. **单写者**：本地存储是物品数据的唯一写入点；云端 remind_plan 只是"提醒任务的影子"；
2. **影子数据可重建**：remind_plan 丢失/被清 → 端侧在下次用户授权订阅时重新上报；
3. **家庭共享（P1）例外**：共享物品以云端为权威（多写者），采用"后保存者 + 合并备注"策略
   （03 GWT-27），届时单独设计冲突矩阵（列入 10 §3 的 P1 技术增量）。
